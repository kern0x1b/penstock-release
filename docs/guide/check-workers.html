Check Workers

Check Workers asks your engine whether anything picks up the tasks your diagrams hand out, before your users find out.

Pro Team in a pipeline

What is a worker

A service task does not do the work itself. A worker, a program of yours, does. On Camunda 8 the task names a job type. On Camunda 7 it names a topic. If no worker is running for that name, the task waits forever. Check Workers finds that out.

Steps

Run Check Workers on the workers of your project. Penstock asks each diagram's engine, using the profile in force for that diagram's folder. A project with a Camunda 7 folder and a Camunda 8 folder asks both. Each worker then says what the engine said, and the workers node shows when the check ran, for example checked at 14:02.

Run Check Workers in your tool

JetBrains

  1. Open the Penstock tool window and find Workers.
  2. Right-click Workers, or select it and use its action: Check Workers on <engine>. If your project uses several engines it says Check Workers on the Engines.

Command line

Not available on the command line. There is no command for it yet. penstock code compares diagrams with code, without asking an engine.

VS Code

Not available in VS Code. VS Code has no Check Workers yet. The Code view in the Explorer lists the workers but has no action that asks an engine, and an action it does not know says "not available in VS Code yet".

What it says

EngineAnswerMeaning
Camunda 8.9 and later3 workers took its jobs in the last 24 hoursAll is well.
Camunda 8.9 and later5 jobs in the last 24 hours and no worker took oneNobody picks up this job type. The worker is marked with a warning.
Camunda 8.9 and laterno jobs in the last 24 hoursNothing to judge.
Camunda 7, Operaton, CIB sevena worker is working on its tasksAll is well.
Camunda 7, Operaton, CIB seventasks wait and no worker has locked oneNobody subscribes to this topic. The worker is marked with a warning.
Camunda 7, Operaton, CIB sevenno open tasksNothing to judge.

When the engine is asked

Only when you run it, with the profile's credentials. See Security and privacy.

Free and paid parts

Check Workers is part of Pro's code links. The code check, which compares diagrams with your code and does not ask an engine, is described on its own page.

Common problems

"The engine does not report job statistics, which it does from Camunda 8.9".
Your Camunda 8 is older than 8.9. Use the code check instead. It compares diagrams with your code.
"The engine refused the question (403)".
The profile's user may not read jobs. Use a user that may.
There is no Check Workers action.
The project has no worker tasks yet, or Pro is not active. Without Pro a Code line offers to buy or sign in.
It says "no jobs" for a worker that runs.
Only the last 24 hours count on Camunda 8, and only open tasks on Camunda 7. A quiet worker looks quiet.
