Troubleshooting and FAQ

Most reports come down to one of a handful of causes: an untrusted project, a configuration that is not where Penstock looks for it, or an engine that answered with an error the message then repeated word for word. This page covers those, and says where to look when none of them fit.

The editor area is blank

The diagram editor is a JCEF browser embedded in the IDE. The plugin declares the platform's JCEF modules as hard dependencies and has no second rendering path, so an IDE that cannot supply JCEF cannot show a diagram at all. JetBrains' own distributions run on the JetBrains Runtime, which includes it; if the IDE has been pointed at a different Java runtime, point it back before investigating anything else.

The editor needs no licence. A paid feature, such as auto layout, says what it does and offers to buy it or to sign in when you reach for it; the rest of the editor carries on working.

Whatever the diagram is doing, the raw XML is never locked away. Penstock registers itself before the IDE's default editor rather than replacing it, so the editor tabs still switch to the plain XML view of the same file.

A file does not open in its editor

The BPMN file type is registered for the extensions bpmn, bpmn.xml and bpmn20.xml, and the DMN file type for dmn. If such a file still opens as plain XML, the pattern has probably been assigned to another file type in the IDE's file type settings; move it back to BPMN or DMN. A .form file opens in the form editor only when it is a Camunda Form, a JSON object with components; any other .form file is left to the IntelliJ GUI Designer.

The tool window only lists files inside a project content root. A diagram kept outside the project's content will not appear there.

Lint findings do not appear

bpmnlint needs no setup: without a configuration the editor applies bpmnlint:recommended, and a .bpmnlintrc in the project root replaces it. See Validation.

No markers on the canvasThe linting button on the canvas turns them off and on, and it is hidden while token simulation runs. The findings are also listed under Rules in the diagram check.
The bpmnlint rules could not runShown under Rules in the diagram check. Usually the .bpmnlintrc uses a bpmnlint plugin, which the editor can only load from a bundle named by lint.clientBundlePath in penstock.yaml.
My own rules are ignoredlint.configPath is relative to the project root. penstock doctor prints the rules file it uses, or says that it is missing.
Running Penstock requires trusting this project firstThe command-line actions in the Penstock tool window start an external process, which the IDE only permits in a trusted project. Trust the project and run it again.
Penstock could not startThe command-line actions run the project's penstockw, or npx when there is none. node and npx must be on the PATH the IDE inherited.

Deployment fails

When the engine answers with anything outside the 2xx range, the failure notice repeats the status code and the engine's own response body. Read that first — it is the engine talking, not Penstock. A request that never reached the engine reports Could not reach the engine at <url> instead.

Camunda 7 endpointThe address has /deployment/create appended. The deployment name defaults to Penstock deployment.
Camunda 8 endpoint/v2/deployments is appended; an address that already ends in /v2 works as well. The IDE and penstock deploy use the same address.
No engine addressNeither deployment.url nor the Connection dialog gives one for the profile in force. Enter it under Connection…, in the menu next to Deploy.
OAuthA failed token request is reported separately: the token endpoint could not be reached, answered with an error status and body, or returned no access_token.
The preDeploy hook failedNothing was sent. The hook's output follows the message. In a project the IDE does not trust, a configured preDeploy is not run, and the deployment stops.
Timeouts10 seconds to connect, 30 seconds for the deployment request, 15 seconds for the token request.

Penstock has no option to skip certificate validation, and none is planned. An engine behind a self-signed or private certificate has to be trusted by the Java runtime the IDE is using; otherwise the request fails before the engine is reached.

Secrets are kept in the IDE password safe, separately for each profile, when you save the Connection dialog. To change one, or to forget it, open Connection… from the arrow next to Deploy while that profile is in force. Saving it with Sign in set to Not needed removes the stored secret.

Element templates do not appear

Templates are read from .camunda/element-templates folders next to the diagram or above it, and from the paths elementTemplates lists in penstock.yaml, relative to the project root. The Classic BPMN editor ignores them, so check the engine first.

A listed path that no longer exists contributes nothing and says nothing in the editor, so a moved or renamed template file simply disappears from the palette; penstock doctor reports it as missing. A file larger than 10 MB is skipped, and a file that is not valid JSON is skipped with an entry in the IDE log. Both a single template object and an array of them are accepted. Parsed templates are cached against the file's modification time, so an edit to a template file is picked up on its own; if in doubt, close and reopen the diagram.

The diagram was changed on disk

Penstock watches the open file. When it changes outside the editor it asks whether to reload, warning that unsaved edits will be lost if you do, and that your next save will overwrite the external change if you do not. The editor's own saves are not mistaken for external ones, and a rename or move of the open file is followed silently without a prompt.

When none of the above fits

The plugin logs through the IDE's own logger under the jetbrains.bpmn.editor package names, so failures that were swallowed — a template that would not parse, a file that could not be written — are in the IDE log with a stack trace. The diagram itself is a browser: the context menu inside it has an Open DevTools item, which is the fastest way to see a frontend error. The diagram diff viewer forwards its browser console to the IDE log with a [bpmn-preview] prefix.

Project settings live in penstock.yaml, and this machine's in penstock.local.yaml. penstock doctor, or Doctor in the Penstock tool window, prints which files apply, the engine, the profiles and whether the engine can be reached. Personal view settings - the toolbar and Sketchy Drawing - are in ~/.penstock/preferences.json.

Questions

Does Classic mode write vendor-neutral BPMN?

Yes. Classic loads plain bpmn-js with the standard properties panel and none of the Camunda modelling modules, so nothing it edits adds Camunda extension attributes. Data inputs and outputs are written the way BPMN defines them, as a bpmn:ioSpecification, from the Inputs and Outputs groups of the panel; see Engine profiles.

Can I jump from a delegate class name to the class in my project?

Yes. Right-click a task that names a Java class - camunda:class, a delegate expression that unwraps to a fully qualified name, or a listener that names one - and choose Go to that class. See Editing a diagram.

Does the plugin send my diagrams anywhere?

No. The only outbound requests the plugin makes with a diagram are the deployment itself and, for OAuth, the token request to the endpoint you configured. Apart from those, it checks the licence with the licence service once a day, and a command-line action downloads the penstock CLI the first time it needs it. The connector template catalogue is served from resources bundled inside the plugin, not fetched. Nothing is reported, and there is no telemetry.

Which IDEs are supported?

Any JetBrains IDE from 2025.2 onwards that ships JCEF, which the standard distributions do. Two builds are published, one for 2025.2 to 2026.1 and one for 2026.2 and later; the Marketplace picks the right one.

Is there a free version?

Yes. Penstock is free on the JetBrains Marketplace, and the editors, the properties panels, templates, token simulation, the check, lint, deployment and export stay free. Pro and Team add auto layout, flow analysis, the diagram diff, the review bot and more; every machine starts with 30 days of Pro. See Plans and licence.

How do I report a bug?

Open a GitHub issue. A .bpmn file that reproduces the problem saves the most time; the IDE log and the engine profile help too. Security problems go to SECURITY.md rather than a public issue.
