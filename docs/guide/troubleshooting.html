Troubleshooting and FAQ

Most reports come down to one of a handful of causes: a missing path, an untrusted project, a file type that was never registered, or an engine that answered with an error the dialog then repeated word for word. This page covers those, and says where to look when none of them fit.

The editor area is blank

The diagram editor is a JCEF browser embedded in the IDE. The plugin declares the platform's JCEF modules as hard dependencies and has no second rendering path, so an IDE that cannot supply JCEF cannot show a diagram at all. JetBrains' own distributions run on the JetBrains Runtime, which includes it; if the IDE has been pointed at a different Java runtime, point it back before investigating anything else.

If the tab is not blank but reads A valid license is required to use Penstock with a Buy License button, the plugin loaded correctly and the licence check returned nothing. Penstock has no free tier; the Marketplace grants a 30-day trial.

Whatever the diagram is doing, the raw XML is never locked away. Penstock registers itself before the IDE's default editor rather than replacing it, so the editor tabs still switch to the plain XML view of the same file.

A .bpmn20.xml file opens as plain XML

The BPMN file type is registered for the extensions bpmn and bpmn.xml. A file named order.bpmn20.xml matches neither, so the IDE opens it with the XML editor. Other parts of the plugin do recognise that suffix by name — the BPMN Project tool window lists files ending in .bpmn and .bpmn20.xml — which is why such a file can appear in the tree and still refuse to open as a diagram. Add the pattern to the BPMN file type in the IDE's file type settings, or rename the file.

The tool window only lists files inside a project content root. A diagram kept outside the project's content will not appear there.

Validation does nothing

Validation stays off until all three paths in Settings | Tools | Penstock, under BPMN Lint Configuration, are set: bpmnlint binary:, .bpmnlintrc config: and client.bundle.js:. The rule is all-or-none. Applying the page with one or two of them filled in is rejected with All three BPMN Lint paths must be configured, and a path that does not exist on disk is rejected with <path> not found.

Nothing happens, no messageOne of the three paths is blank, so linting is disabled. The plugin reports that it could not find the bpmnlint npm package.
Requires trusting this projectbpmnlint runs an external process, which the IDE only permits in a trusted project. Trust the project and run it again.
Failed to run bpmnlintThe linter is started as node with the configured binary as its first argument. node must be on the PATH the IDE inherited.
Already runningOne run per file at a time. Wait for the current run, or stop it from the run panel.
Execution timed outA run is killed after 180 seconds.

The process runs with its working directory set to the folder holding .bpmnlintrc, so relative plugin resolution is relative to that folder, not to the diagram. Output appears in a run tab titled BPMN Lint – <file name>.

Deployment fails

When the engine answers with anything outside the 2xx range, the failure notice repeats the status code and the engine's own response body. Read that first — it is the engine talking, not Penstock. A request that never reached the engine reports Failed to reach Camunda engine at <url> instead.

Camunda 7 endpointThe base URL you enter has /deployment/create appended. A deployment name is required; basic authentication is the only scheme offered.
Camunda 8 endpoint/deployments is appended unless the URL already ends with it. Basic, bearer token, OAuth 2.0 client credentials and API key are available.
OAuth 2.0A failed token request is reported separately, as OAuth2 token request failed with the token endpoint's status and body, or as a missing access_token.
Timeouts10 seconds to connect, 30 seconds for the deployment request, 15 seconds for the token request.
Camunda 8 under loadA 503 mentioning RESOURCE_EXHAUSTED is reported as engine backpressure. Retry with a backoff.

Penstock has no option to skip certificate validation, and none is planned. An engine behind a self-signed or private certificate has to be trusted by the Java runtime the IDE is using; otherwise the request fails before the engine is reached.

Secrets are written to the IDE password safe only when save credentials is on, and are cleared from it when you turn that off. With it off, a password or token has to be entered each time — that is the setting, not a bug.

Element templates do not appear

The Element Templates group in Settings | Tools | Penstock is shown only when the project's engine is Camunda 8. If you cannot find it, check the engine first.

Templates are remembered as file paths. A path that no longer exists contributes nothing and says nothing, so a moved or renamed template file simply disappears from the palette. A file larger than 10 MB is skipped, and a file that is not valid JSON is skipped with an entry in the IDE log. Both a single template object and an array of them are accepted. Parsed templates are cached against the file's modification time, so an edit to a template file is picked up on its own; if in doubt, close and reopen the diagram.

The diagram was changed on disk

Penstock watches the open file. When it changes outside the editor it asks whether to reload, warning that unsaved edits will be lost if you do, and that your next save will overwrite the external change if you do not. The editor's own saves are not mistaken for external ones, and a rename or move of the open file is followed silently without a prompt.

When none of the above fits

The plugin logs through the IDE's own logger under the jetbrains.bpmn.editor package names, so failures that were swallowed — a template that would not parse, a file that could not be written — are in the IDE log with a stack trace. The diagram itself is a browser: the context menu inside it has an Open DevTools item, which is the fastest way to see a frontend error. The auto layout preview forwards its browser console to the IDE log with a [bpmn-preview] prefix.

Project settings live in bpmn-project.xml in the project's IDE configuration folder. Deleting it resets the engine choice, the lint paths and the template list for that project, and nothing else.

Questions

Does Classic mode write vendor-neutral BPMN?

Yes, for what it writes. Classic loads plain bpmn-js with the standard properties panel and none of the Camunda modelling modules, so nothing it edits adds Camunda extension attributes. The limitation worth knowing is on the other side: there is no editor for standard ioSpecification data inputs and outputs. The element tooltip will read them out of a diagram that already has them, but the panel cannot create them.

Can I jump from a delegate class name to the class in my project?

Not yet. The element tooltip shows a delegate expression as text; it is not a link, and there is no navigation action. It is on the roadmap.

Does the plugin send my diagrams anywhere?

No. The only outbound requests the plugin makes are the deployment itself and, for OAuth 2.0, the token request to the endpoint you configured. The connector template catalogue is served from resources bundled inside the plugin, not fetched. Nothing is reported, and there is no telemetry.

Which IDEs are supported?

Any JetBrains IDE from 2025.2 onwards that ships JCEF, which the standard distributions do. Two builds are published, one for 2025.2 to 2026.1 and one for 2026.2 and later; the Marketplace picks the right one.

Is there a free version?

No. Penstock is commercial and has no free tier — without a licence the editor shows a notice instead of the diagram. The Marketplace grants a 30-day trial.

How do I report a bug?

Open a GitHub issue. A .bpmn file that reproduces the problem saves the most time; the IDE log and the engine profile help too. Security problems go to SECURITY.md rather than a public issue.
