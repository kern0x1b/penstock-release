Settings and project files

Penstock is configured per project. Almost everything is set on one settings page and stored by the IDE in a file you should not edit by hand. Auto-layout spacing is the exception: it is read from a file you write yourself.

The settings page

Open Settings | Tools | Penstock. The page belongs to the open project, and it is not offered in the settings for new projects, so open a project first.

The first group is headed '<project name>' Settings.

Default BPMN engineThe engine profile for this project: CLASSIC_BPMN, CAMUNDA_7 or CAMUNDA_8. It decides the palette and the properties panel, whether the script type row appears, and whether the Element Templates group appears.
Color themeSYSTEM, LIGHT, DARK or DRACULA. SYSTEM follows the IDE theme and switches with it. The change is pushed to every open diagram when you apply it.
Scheme themeDEFAULT for the standard BPMN 2.0 rendering, SKETCHY for a hand-drawn style.
Default script typeBlank, groovy or javascript. Shown only when the engine is CAMUNDA_7.
Show text labels on toolbar buttonsOff by default. Adds text beside the icons in the editor toolbar.

BPMN Lint Configuration

Three paths, each with a browse button: the bpmnlint binary (for example node_modules/.bin/bpmnlint), the .bpmnlintrc config, and client.bundle.js (for example .bpmnlint/client.bundle.js).

The three are all-or-none. Leave every field empty to turn linting off. If you fill in one, you must fill in all three, and each file must exist — applying a partial or broken set is refused with an error rather than saved.

Element Templates

Shown only when the engine is CAMUNDA_8. A list with add and remove buttons. The add action opens a chooser that takes files or folders; a folder is scanned recursively and every .json file inside it is added individually, and a path already in the list is skipped. The list stores absolute file paths, and each file is read from disk when the editor loads its configuration.

About

One link, Open source licenses, which opens the third-party notices bundled with the plugin.

Setting the engine from the editor

A project starts with no engine chosen. Until one is set, opening a BPMN file shows a Configure BPMN Engine screen instead of the modeler, where you pick the engine and, depending on the engine, the script type or the element templates, plus the same three lint paths. Saving there writes the engine, script type, element templates and lint paths into the same project configuration the settings page uses; it does not touch the themes or the toolbar label setting.

Because both routes write the same file, the settings dialog checks before applying. If the configuration changed elsewhere while the dialog was open, it asks whether to overwrite that change, and cancelling leaves the other change in place.

bpmn-project.xml

The IDE stores the project configuration as bpmn-project.xml in the project's .idea directory. It is written by the platform's settings machinery, so treat it as generated: change the values through the settings page, not in the editor.

It holds the engine, colour theme, scheme theme, default script type, the toolbar label setting, the three lint paths, the list of element template paths, whether the BPMN Project tool window is showing its tree view, and the non-secret part of the deployment configuration — base URLs for Camunda 7 and Camunda 8, deployment name, tenant id, deployment source, duplicate filtering, deploy-changed-only, activation time, authentication type, user name, client id, token URL, audience, and whether credentials should be remembered.

Passwords, bearer tokens, client secrets and API keys are never written to it. They go to the IDE password safe, and only when you ask for them to be saved.

.bpmnlayoutrc

Auto-layout spacing comes from a file named .bpmnlayoutrc in the project root. Nothing creates it for you and nothing writes to it; it exists only if you add it. It is read each time auto layout runs, so an edit takes effect on the next run without restarting the IDE.

nodesepInteger, default 40. Pixels between nodes in the same rank.
ranksepInteger, default 80. Pixels between ranks, along the direction of flow.
marginXInteger, default 40. Horizontal margin around the diagram.
marginYInteger, default 40. Vertical margin around the diagram.

The file is JSON, read with Java-style comments and trailing commas allowed, so this is valid:

{
  // more space between rows, less between columns
  "nodesep": 56,
  "ranksep": 64,
  "marginX": 40,
  "marginY": 40,
}

Every field is optional and falls back to its default on its own. If the file is missing, or cannot be parsed, the four defaults are used and auto layout runs as normal — there is no error to dismiss, so check the values here first if a change appears to have no effect.

What belongs in version control

.bpmnlayoutrcCommit it. It is hand-written, it has no machine-specific content, and committing it is what gives everyone on the project the same auto-layout spacing.
.idea/bpmn-project.xmlYour call. It carries no secrets, and committing it gives everyone the same engine profile and deployment targets. Note that element template entries are absolute paths, so they only resolve for people whose checkout sits in the same place.
CredentialsNothing to commit. They live in the IDE password safe, outside the project.
.bpmn and .bpmn20.xmlCommit them. They are the process definitions, and reviewing them alongside code is the point.
