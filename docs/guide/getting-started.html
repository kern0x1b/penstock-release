Getting started

Penstock installs from the JetBrains Marketplace and opens BPMN, DMN and form files in editors inside the IDE. The engine you are modelling for comes from the project's penstock.yaml or from the diagram itself. This page covers the first few minutes after installing.

Requirements

IDEAny JetBrains IDE from 2025.2
Marketplace listingPenstock, id 25710. Published as Camunda BPMN Editor until 2026
LicenceFree on the Marketplace. Pro and Team are paid, and every machine starts with 30 days of Pro
Engine profilesClassic BPMN, Camunda 7, Camunda 8

Everything a modeller needs is free: the editors, the properties panels, element templates, token simulation, the check, lint, deployment and export. A paid feature, such as auto layout or flow analysis, says what it does and offers to buy it or to sign in at the moment you reach for it. See Plans and licence.

Install

  1. Open the plugin manager

    In the IDE, open Settings | Plugins and search the Marketplace for Penstock.

  2. Install and restart

    Install the plugin and restart the IDE when prompted.

  3. Open a BPMN file

    Open any .bpmn file from the Project view or the Penstock tool window, or create one and paste a BPMN 2.0 definition into it.

After an update, Penstock posts a notification saying which version it updated to, with a What's new action that opens the bundled changelog in an editor tab.

Which files open in the editor

Penstock registers a file type called BPMN, described as a BPMN process definition file, for the extensions bpmn, bpmn.xml and bpmn20.xml, with XML as the underlying language. Files of that type open in the diagram editor. A .dmn file opens in the decision editor, and a .form file in the form editor when it is a Camunda Form; a .form file of the IntelliJ GUI Designer is left to the GUI Designer.

The editors are registered ahead of the IDE's own editor rather than in place of it, so the plain text editor stays available for the same file. The editor tabs at the bottom of the editor window switch between them; the diagram tab is called BPMN Editor, and the others DMN Editor and Form Editor.

Changes made in the diagram are written back to the file itself as you make them. There is no separate save step for the diagram: the file is replaced atomically on each change, then refreshed in the IDE, so the XML tab and version control see the new content immediately.

How the engine is chosen

A diagram opens straight away. The engine profile it is edited under comes from engine in the nearest penstock.yaml, and when that is not set, from the diagram itself: the execution platform the Camunda Modeler records, or the zeebe: or camunda: attributes it already carries. See Engine profiles.

Only an empty new diagram, which says nothing about its engine, asks. A single line appears above the canvas, Which engine runs this diagram?, with a button for Camunda 8, Camunda 7 and Plain BPMN. The answer is written into penstock.yaml, which is created in the project root if there is none, and the line does not come back.

The editor window

The editor is a toolbar across the top, the diagram canvas on the left, and the properties panel on the right. The diagram always takes the IDE's theme.

Undo and Redo sit on the left of the toolbar. Every other action is in the More menu, the button marked with three dots, with its icon and its name. The ones used most are also pinned to the toolbar to start with:

Auto LayoutLays the diagram out again, at once. Pro
CheckOpens the diagram check, which lists what is wrong with the diagram
SimulateToggles token simulation
Properties panelAn icon at the right edge, pressed while the panel is open
DeployDeploys the diagram, on the right. Camunda 7 and Camunda 8 only

The rest are in the menu only: Minimap, Copy, Paste, Export…, Templates… (Camunda 8 only) and Sketchy Drawing, which draws the diagram as if by hand. The pin in each row of the menu puts that action on the toolbar or takes it off. The choice, and Sketchy Drawing, are kept in ~/.penstock/preferences.json, so they are the same in every IDE on the machine and survive a restart.

The Penstock tool window

Penstock adds a tool window called Penstock, anchored to the left. It lists every BPMN, DMN and form file in the project under a root node named after the project. Double-clicking a file, or pressing Enter on it, opens it.

Its toolbar has four actions: Run Penstock, a menu of command-line actions; Reload from Disk, which re-reads the project from disk and rebuilds the list; View as Tree, a toggle between the directory structure and a flat list; and Open penstock.yaml, which opens the project's configuration, or creates it when there is none. The list also refreshes by itself when a file in the project is added, changed or removed.

Right-clicking a file gives its context menu:

  • Open opens it in its editor.
  • Copy Process ID copies the id of the first process in the file to the clipboard, for a file that has one.
  • The command-line actions: Check, Paths, Tests, Code, Docs, Format, Diff Since…, Export… and Doctor. Each runs penstock on the file or folder, through the project's penstockw when there is one, and shows the output in the Run window. They need the project to be trusted, and Paths, Tests, Code and Docs are Pro.
