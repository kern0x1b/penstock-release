Getting started

Penstock installs from the JetBrains Marketplace and opens BPMN, DMN and form files in editors inside the IDE. The engine you are modelling for comes from the project's penstock.yaml or from the diagram itself. This page covers the first few minutes after installing.

Requirements

IDEAny JetBrains IDE from 2025.2 with JCEF, which the standard distributions bundle
Marketplace listingPenstock, id 25710. Published as Camunda BPMN Editor until 2026
LicenceFree on the Marketplace. Pro and Team are paid, and every machine starts with 30 days of Pro
EnginesClassic BPMN, Camunda 7, Camunda 8, Operaton, CIB seven

Everything a modeller needs is free: the editors, the properties panels, element templates, token simulation, the check, lint, deployment, Monitor and export. A paid feature, such as auto layout or flow analysis, says what it does and offers to buy it or to sign in at the moment you reach for it. See Plans and licence.

Install

  1. Open the plugin manager

    In the IDE, open Settings | Plugins and search the Marketplace for Penstock.

  2. Install and restart

    Install the plugin and restart the IDE when prompted.

  3. Open a BPMN file

    Open any .bpmn file from the Project view or the Penstock tool window, or create one and paste a BPMN 2.0 definition into it.

After an update, Penstock posts a notification saying which version it updated to, with a What's new action that opens the bundled changelog in an editor tab. Nothing is shown on a fresh install.

Start from an example

If the project has no diagrams yet, the Penstock tool window offers to create one of two small projects, each of which runs into a local engine:

Camunda 8 order processAn order process with a service task, a user task with a Camunda Form, a decision, a message and an error boundary, with a Spring Boot worker and a Node worker
Camunda 7 order processThe same process with a Java delegate and an external task worker

Either way you get test cases in the Camunda format, a penstock.yaml and a README with the commands to run it. penstock init --example camunda-8 or --example camunda-7 writes the same thing into an empty folder from a terminal. See Command line.

Which files open in the editor

Penstock registers a file type called BPMN, described as a BPMN process definition file, for the extensions bpmn, bpmn.xml and bpmn20.xml, with XML as the underlying language. Files of that type open in the diagram editor. A .dmn file opens in the decision editor, and a .form file in the form editor when it is a Camunda Form; a .form file of the IntelliJ GUI Designer is left to the GUI Designer.

The editors are registered ahead of the IDE's own editor rather than in place of it, so the plain text editor stays available for the same file. The editor tabs at the bottom of the editor window switch between them; the diagram tab is called BPMN Editor, and the others DMN Editor and Form Editor.

Changes made in the diagram are written back to the file itself as you make them. There is no separate save step for the diagram: the file is replaced atomically on each change, then refreshed in the IDE, so the XML tab and version control see the new content immediately.

How the engine is chosen

A diagram opens straight away, fitted into the canvas. The engine profile it is edited under comes from engine in the nearest penstock.yaml, and when that is not set, from the diagram itself: the execution platform the Camunda Modeler records, or the zeebe:, camunda: or operaton: attributes it already carries. See Engine profiles.

Only an empty new diagram, which says nothing about its engine, asks. A single line appears above the canvas, Which engine runs this diagram?, with a button for Camunda 8, Operaton, CIB seven, Camunda 7 and Classic BPMN. The answer is written into penstock.yaml, which is created in the project root if there is none, and the line does not come back.

The first minute

The first time the editor opens it walks you through six things in a few words each: the palette, the properties panel, Check, the Penstock tool window - which it points out is on the stripe at the side of the IDE - Deploy, and the More menu. It is shown once, and the fact that it has been seen is kept in ~/.penstock/preferences.json beside the toolbar choices. Show the tour again is in the More menu, under Help.

The editor is a toolbar across the top of the canvas, the diagram in the middle, and the sidebar on the right. The diagram always takes the IDE's theme.

Undo and Redo sit on the left of the toolbar. Deploy is the one primary action, on the right, and the sidebar toggle is the last thing on the bar. Everything else is in the More menu, the button marked with three dots, and the same list opens with Ctrl+Alt+, or ⌥⌘,. The actions used most are pinned to the toolbar to start with:

Auto layoutLays the diagram out again, at once. Pro
CheckOpens the Problems tab, which lists what is wrong with the diagram
SimulateToggles token simulation
MonitorWhat the engine is doing with this diagram
ScenariosThe test cases of this process, and running them. Pro
CoverageWhat the process tests reach. Pro
Migrate to Camunda 8On a Camunda 7, Operaton or CIB seven diagram
SidebarAn icon at the right edge, pressed while the sidebar is open
DeployOpens the Deploy popover. Camunda 7 family and Camunda 8 only

The pin in each row of the menu and of the command palette puts that action on the toolbar or takes it off, and the choice is kept in ~/.penstock/preferences.json, so it is the same in every IDE on the machine and survives a restart. See Editing a diagram.

The Penstock tool window

Penstock adds a tool window called Penstock, anchored to the left. It shows the project as a model rather than a list of files: the processes with the processes they call and are called by, the workers every task needs, the messages with who catches and throws them, the decisions and forms with the tasks that use them, the deployment profiles with their addresses and the last deploy, the tests and what they cover, and the files themselves. Group by Files turns it round, file by file. Double-clicking anything opens it and selects the element on the diagram.

Its toolbar has a Run Penstock menu of command-line actions, Reload from Disk, which re-reads the project from disk, View as Tree, a toggle between the directory structure and a flat list, and Open penstock.yaml, which opens the project's configuration or creates it when there is none. The list also refreshes by itself when a file in the project is added, changed or removed.

Right-clicking a file gives its context menu:

  • Open opens it in its editor.
  • Copy Process ID copies the id of the first process in the file to the clipboard, for a file that has one.
  • The command-line actions: Check, Paths, Tests, Code, Docs, Format, Diff Since…, Export… and Doctor. Each runs penstock on the file or folder, through the project's penstockw when there is one, and shows the output in the Run window. They need the project to be trusted, and Paths, Tests, Code and Docs are Pro.
