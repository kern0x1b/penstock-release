Plans and licence

Penstock is free on the JetBrains Marketplace, and everything a modeller needs stays free. Pro and Team add the parts that save a team real time: laying a diagram out, proving it runs, linking it to the code, and reviewing it in a pull request. Every machine starts with thirty days of Pro.

One rule

A paid feature needs Pro on a developer's machine and Team inside a pipeline, which is any run with CI set. There are no exceptions per feature or flag: the review bot, SARIF and annotations, baselines and report run locally on Pro, and every paid command in a pipeline needs Team. penstock init --ci writes a pipeline for the licence the machine has, so nobody's first run fails on a feature nobody has bought.

What each plan includes

FreeThe diagram, decision and form editors with the Classic BPMN, Camunda 7, Camunda 8, Operaton and CIB seven profiles; the properties panels; the command palette and every action in it; the sidebar, the check card and the Problems tab; element templates and the connector browser; scripts in an IDE tab; going from a Camunda 7 delegate to its class or bean; token simulation; transaction boundaries; the drawing check and bpmnlint with the engine compatibility rules; the Camunda 7 to Camunda 8 analysis and its report; deployment; Monitor; sharing a diagram as one HTML file; importing draw.io, Visio, Signavio and Bizagi; export; and the hand-drawn look. In the terminal: check with its drawing and rules sections, migrate analyze, fmt, diff, export, share, import, show, deploy, doctor, mcp for reading and checking.
ProAuto layout; flow analysis, which finds deadlocks, branches that run twice, steps that can never run and loops with no way out, and shows the path that leads there; the link between diagrams and code, which is the way from a step to its worker and back, usages, Code Vision, variables and error codes across both, tests run from the diagram, coverage on it, linked repositories and Check Workers; scenarios, every distinct way through a process with the conditions it takes, and a test-case run against a local engine with mocks; a JUnit test for each way; documentation for every process, decision and form; converting a Camunda 7 diagram to Camunda 8, with the visual diagram diff before anything is written; modelling conventions from penstock.yaml; pictures of what changed; editing from the command line; and, on your machine, the pull request report, check baselines and findings as SARIF or GitHub annotations.
TeamEverything in Pro, in a pipeline as well: the review bot in pull and merge requests, the pull request report, check baselines, findings as SARIF or GitHub annotations, converting a Camunda 7 project, and every other paid command inside CI.

A paid feature you have not bought says what it does and offers to buy it or to sign in, at the moment you reach for it. Nothing else in the editor changes, and the diagram opens as usual.

Buying

Pro and Team are monthly or yearly. The price is shown at the checkout, which is where the plan is chosen, so nothing here goes out of date.

In the IDE, click Penstock in the status bar or choose Tools | Penstock Licence…. Signing in is one field, E-mail or licence key, with Buy Pro beside it and a link to buy Team. In a terminal, run penstock license buy or penstock license buy team. The checkout opens in your browser; yearly billing is selected, and monthly is one click away. Once the payment goes through, Penstock notices by itself and sends a sign-in code to the address that paid; type it in and the licence is active. There is no key to copy.

Payments are handled by Polar, the reseller and merchant of record, which also takes care of VAT and invoices. Cancel at any time from the link in the receipt. The full terms are in the licence.

One licence for the IDE and the terminal

The licence lives in ~/.penstock, and the editor and penstock both read it: sign in once on a machine and both are licensed. On another machine, type the address you bought it with into the sign-in field - it gets a code - or run penstock license login. A key works in the same field too.

A licence covers a number of machines at once. Signing in again on the same machine, after reinstalling the IDE for example, reuses its place rather than taking a new one. When every place is taken, signing in lists the machines and frees the one you pick. Release This Machine or penstock license logout does the same by hand.

How the licence is checked

The licence is a signed token, not a flag. A small service turns the answer from Polar into a token signed with a key only it holds, and the plugin, the command line and the editor carry the public half and check the signature themselves, offline. A file edited by hand, a redirected address or a server pretending to be the licence service cannot make a machine Pro.

The token belongs to one machine, lasts thirty days, and is renewed once a day when the machine is online. Offline it keeps working until it runs out, and the editor says how many days are left rather than stopping. A machine whose clock has been set back is refused, with the reason given.

What is on the machine is the token and nothing else: no key, no tier, no date you could edit. penstock license says which licence this machine has and where it comes from, and during the trial it says the trial is on and until when, instead of saying there is no licence.

The thirty-day trial

Every machine gets thirty days of Pro from its first use. The start date is kept by the licence service rather than on the machine, so deleting files no longer starts a new one, and a machine clock cannot move it.

This release moves the licensing to Polar, so every machine starts a fresh thirty-day Pro trial with it. An earlier trial does not carry over: the old trial file is ignored and removed, and nothing about it is read again.

A pipeline gets no trial. A trial is for a person at a machine.

In a pipeline

A pipeline does not sign in. A Team key is stored as a secret named PENSTOCK_LICENSE, and Copy Key for CI or penstock license key finds it again by the same e-mail code, since the machine no longer keeps it. The key is only honoured when CI is set, and it is exchanged for a short-lived token rather than used as a flag. The pipelines penstock init --ci writes already pass it through, when the machine that ran it has Team; without Team it writes a pipeline that runs the free check, so its first run does not fail on a feature nobody has bought.

Commands

license buy [pro|team]Open the checkout, wait for the payment and activate the licence.
license login [email]Sign in with the address you bought Penstock with.
license logoutRelease this machine so the licence can be used on another.
licenseWhich licence this machine has and where it comes from. license key prints the key for a pipeline; license activate <key> activates a key typed in by hand.

For an AI agent

The MCP server is priced tool by tool rather than as a whole. list_diagrams, show_diagram and check_diagram only read and explain a diagram, so they are free. analyze_flow needs flow analysis, list_scenarios needs scenarios list, check_code_links needs code, and edit_diagram needs edit: the same tier those commands need on the command line. A tool called without the licence says in its result what it gives and how to buy or sign in, and still appears in tools/list with a note on what it needs. See Command line.
