Plans and licence

Penstock is free, and what only Penstock does is Pro or Team. One rule decides which one a feature needs.

The one rule

Everything that earlier releases had, and everything other tools give away, is free. What only Penstock does is Pro or Team.

A paid feature needs Pro on your own machine and Team inside a pipeline. A pipeline is any run where the environment variable CI is set. There are no exceptions for a single feature or a single flag.

Every machine starts with 30 days of Pro. A pipeline gets no trial.

What each plan gives

PlanWhat it includes
Free

In the IDE: the BPMN, DMN and form editors, the properties panels, element templates and the connector browser, scripts in an IDE tab, token simulation, the diagram check with the drawing and the bpmnlint rules, deploy, Live, export, the hand-drawn look, opening a run that already exists, going from a Camunda 7 delegate to its class or bean, sharing a diagram as one HTML file, and importing from draw.io, Visio, Signavio and Bizagi.

The Camunda 7 to Camunda 8 analysis and its report are free too.

On the command line: init, doctor, check (the drawing and rules sections), migrate analyze and migrate report, fmt, diff, export, show, deploy, share, import, connectors, license, update, and edit --schema.

The MCP tools list_diagrams, show_diagram and check_diagram, which only read and explain.
Pro
on your machine
  • Auto layout.
  • Flow analysis, and the decision table and form checks.
  • The visual diagram diff, and pictures of what changed.
  • Modelling conventions from penstock.yaml.
  • Converting Camunda 7 to Camunda 8: the preview, penstock migrate convert and the job worker skeletons.
  • Test-case runs.
  • The link between diagrams and code in the IDE: code links. From a step to its worker and back, usages, Code Vision, variables and error codes across both, tests run from the diagram, coverage on it, the debugger's position on the diagram, linked repositories, and Check Workers.
  • In the command line: layout, check --only flow, paths, tests, test-cases, code, docs, diff --images, edit, report, check baselines, and findings as SARIF or GitHub annotations.
  • The review bot, when you run it on your machine.
  • The MCP tools analyze_flow, list_scenarios, check_code_links and edit_diagram. Each needs the same plan as its command line twin.
Team
in a pipeline

Everything in Pro, inside a pipeline. That includes the review bot in pull and merge requests, the pull request report, check baselines, and findings as SARIF or GitHub annotations in the code review. Every paid command in a pipeline needs Team.

Not sure what a page needs? The tag under its title says. Free means free. Pro means a paid feature.

What you see when you reach a paid feature

Nothing else in the editor changes. When you reach for a paid feature you do not have, Penstock explains what it does and offers to buy it or to sign in, at that moment.

  • In the IDE, a dialog says, for example, Auto layout is part of Penstock Pro. and offers Buy Pro, I Already Bought It and Not Now. If your trial has ended it says so.
  • In a terminal, the command prints what the feature gives and the commands penstock license buy and penstock license login. In a pipeline it says the feature needs Team and to give the pipeline a key in PENSTOCK_LICENSE.
  • An MCP tool called without the licence says the same in its error result. It also shows in the tool list with a note on what it needs.

Free Pro for students, teachers and open-source maintainers

Students, teachers and open-source maintainers can get Pro for free. When the application link is set up, the licence dialog, the message that explains a paid feature, and penstock license show it. See Buying and signing in.

Common problems

A feature that worked yesterday now asks me to buy Pro.
Your 30-day trial has ended, or your licence was released or ended. Run penstock license to see which licence this machine has.
It works on my laptop but the pipeline says it needs Team.
That is the rule: a pipeline needs Team for every paid feature. penstock init --ci writes a pipeline for the licence on the machine that ran it, so its first run does not fail on something nobody bought.
Which plan do I need for the review bot?
Team in a pipeline. Pro is enough to run it on your own machine.
