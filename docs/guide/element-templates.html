Element templates and connectors

An element template is a JSON file that turns a plain task or event into a pre-configured one, with its own properties panel. Penstock reads templates from the folders Camunda Modeler uses and from the ones penstock.yaml lists, and ships a browser for the Camunda connector templates so you can install one without leaving the IDE.

Where templates come from

Two places, and nothing else in the project is scanned:

  • A folder named .camunda/element-templates, next to the diagram or in any folder above it up to the project root. That is where Camunda Modeler keeps templates, and they are used without being listed.
  • The files and folders listed under elementTemplates in penstock.yaml, relative to the project root. A folder is read whole, with every .json file in it and in the folders below it.
elementTemplates:
  - templates/connectors
  - shared/payment-task.json

Like the rest of penstock.yaml, the list can differ per folder: the file nearest the diagram wins. See Configuration.

What Penstock does with each file

Every listed file is read and parsed as JSON. A file may contain a single template object or an array of them; both are accepted, and an array is expanded into its members. The parsed templates are handed to the modeler when a diagram opens, so the properties panel can offer them.

Three cases are handled quietly rather than with an error dialog:

  • A path that no longer exists is skipped.
  • A file larger than 10 MB is skipped, and a warning is written to the IDE log.
  • A file that fails to parse is skipped, and the error is written to the IDE log with the path.

Results are cached per file and invalidated by the file's modification time, so editing a template on disk is picked up without restarting the IDE.

Penstock does not define the template format — it consumes the Camunda one. For the schema, the binding types and the property definitions, see Camunda's own element template documentation.

The connector browser

Templates… in the editor's More menu opens Element Templates Marketplace, a browser over the Camunda connector templates bundled with the plugin. The menu item is present only when the diagram's engine profile is Camunda 8.

The catalogue is part of the plugin. The template files are taken from the camunda/connectors repository when the plugin is built, and are read from disk at runtime, so the browser works without network access and without a Camunda account.

The left sidebar has a search box, an Installed only toggle and a Categories list with a count against each entry. The list starts with All Connectors, then the eight fixed categories:

CommunicationMessaging and notification connectors
Cloud & InfrastructureCloud provider services
Business ApplicationsCRM, service management, project and content tools
Data & MessagingDatabases, brokers, HTTP and file formats
DevelopmentSource hosting and CI
AI & Machine LearningModel inference and agent connectors
Automation & RPARobotic process automation and orchestration
OtherThe Camunda-specific connectors, and anything the catalogue has no category for

Each connector is a card carrying its description, its template count and its category, with a Details button. For a connector with one template that opens the template straight away; for a connector with several it opens the list first, and you pick one from there.

A template's own view shows its description, the element type it creates, the BPMN element types it applies to, the engine versions it declares, the number of properties that are not hidden, and the properties themselves under the template's own groups, with anything ungrouped collected under Other Properties. Where the template carries a documentation reference, a View Documentation link opens it in a browser.

Installing from the browser

Installing writes the template file into your project, in one action. Save it into a .camunda/element-templates folder, or into a folder elementTemplates already lists, and every diagram that looks there picks it up:

  1. The template is read and parsed

    The JSON is read from the bundled catalogue and parsed first, so a template that would not load never reaches the next step.

  2. Choose where it goes

    A save dialog opens, pre-filled with the template's own file name. Nothing is written if you cancel.

  3. The file is written

    The template JSON is saved to the path you picked.

  4. The configuration is updated, the first time

    When the project's penstock.yaml has no elementTemplates list yet, the new file becomes its first entry. A list that is already there is not changed.

  5. The open diagram picks it up

    The template is applied to the running modeler immediately. You do not have to reopen the diagram or restart the IDE.

For a connector that ships several templates, the card's install button takes every template of that connector you do not already have. That path asks for a folder rather than a file name, then warns that it will write one file per template into that folder and overwrite existing files with the same names, and waits for you to confirm. Each file is saved under the template's own file name; progress is shown on the connector's button. To take one template of such a connector on its own, open Details and install it from the list.

Templates already present are marked as installed and their install buttons are disabled. A catalogue template counts as present when an entry in elementTemplates ends in the same file name, or when a template already loaded for the diagram carries the same name.

Camunda 7 and Classic BPMN

Only the connector browser is gated on Camunda 8: under Camunda 7 or Classic BPMN the More menu has no Templates….

Loading is not gated the same way. The templates are read and handed to the editor whichever profile the diagram uses. The Camunda 7 editor applies templates — it carries the same element template properties provider and template chooser as the Camunda 8 one — so Camunda 7 templates in .camunda/element-templates work there as well. The Classic BPMN editor has no element template support at all, and templates handed to it are ignored.

When a template does not appear

Check, in this order: that the diagram's engine profile is Camunda 8 or Camunda 7 rather than Classic BPMN, that the file is in a .camunda/element-templates folder at or above the diagram or under a path elementTemplates lists, relative to the project root, and that the file still exists there. penstock doctor reports a listed path that is missing. If all of that holds, look in the IDE log — a file that is too large or does not parse is skipped with a message naming the path.
