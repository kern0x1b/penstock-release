Element templates

An element template is a JSON file that turns a plain task or event into a pre-configured one, with its own properties panel. Penstock reads templates from the folders Camunda Modeler uses and from the ones penstock.yaml lists, and ships a browser for Camunda's connector templates so you can install one without leaving the IDE.

Where templates come from

Two places, and nothing else in the project is scanned:

  • A folder named .camunda/element-templates, next to the diagram or in any folder above it up to the project root. That is where Camunda Modeler keeps templates, and they are used without being listed.
  • The files and folders listed under elementTemplates in penstock.yaml, relative to the project root. A folder is read whole, with every .json file in it and in the folders below it.
elementTemplates:
  - templates/connectors
  - shared/payment-task.json

Like the rest of penstock.yaml, the list can differ per folder: the file nearest the diagram wins. See Configuration.

What Penstock does with each file

Every listed file is read and parsed as JSON. A file may contain a single template object or an array of them; both are accepted, and an array is expanded into its members. The parsed templates are handed to the modeler when a diagram opens, so the properties panel can offer them.

Three cases are handled quietly rather than with an error dialog:

  • A path that no longer exists is skipped.
  • A file larger than 10 MB is skipped, and a warning is written to the IDE log.
  • A file that fails to parse is skipped, and the error is written to the IDE log with the path.

Results are cached per file and invalidated by the file's modification time, so editing a template on disk is picked up without restarting the IDE.

Penstock does not define the template format - it consumes the Camunda one. For the schema, the binding types and the property definitions, see Camunda's own element template documentation.

The connector browser

Templates… in the File section of the editor's More menu opens Element Templates Marketplace, a browser over Camunda's connector templates. The menu item is present only when the diagram's engine profile is Camunda 8.

Where the catalogue comes from

The connector templates are not bundled with the plugin. They are downloaded from GitHub, from api.github.com and codeload.github.com, the first time you open the browser or press Download on a template the diagram is missing. Nothing is fetched at IDE startup, and nothing is fetched when a diagram opens on its own.

The download is cached in ~/.penstock/connectors/<ref>/, where the IDE and penstock share it, so the command line reads the same templates the browser shows. Opening a diagram resolves templates from that cache without a network request, so a project opens the same way offline as online.

Downloads are refreshed at most once a day, send no credentials, no cookies and no project data, follow the IDE's proxy settings, and fall back to the cache when the network is not there. A proxy or a firewall that blocks the download is therefore a slow catalogue, not a broken editor.

The list

The left sidebar has a search box, an Installed only toggle and an Categories list with a count against each entry. The list starts with All Connectors, then the eight fixed categories:

CommunicationMessaging and notification connectors
Cloud & InfrastructureCloud provider services
Business ApplicationsCRM, service management, project and content tools
Data & MessagingDatabases, brokers, HTTP and file formats
DevelopmentSource hosting and CI
AI & Machine LearningModel inference and agent connectors
Automation & RPARobotic process automation and orchestration
OtherThe Camunda-specific connectors, and anything the catalogue has no category for

Each connector is a card carrying its description, its template count, its category and its version, with a Details button. For a connector with one template that opens the template straight away; for a connector with several it opens the list first, and you pick one from there. A template Camunda has deprecated is badged Deprecated, with its own reason where the template gives one, and sorted after the current ones rather than in among them alphabetically.

A template's own view shows its description, the element type it creates, the BPMN element types it applies to, the engine versions it declares, the number of properties that are not hidden, and the properties themselves under the template's own groups, with anything ungrouped collected under Other Properties. Where the template carries a documentation reference, a View Documentation link opens it in a browser. The details are shown inside the browser itself rather than in a second window.

Installing from the browser

Installing writes the template file into your project, in one action. The save panel opens in the nearest .camunda/element-templates folder above the diagram, using one that already exists where the project has one, so the template lands where the editor will look for it. Nothing is written if you cancel.

  1. The template is read and parsed

    The JSON is read from the catalogue and parsed first, so a template that would not load never reaches the next step.

  2. Choose where it goes

    A save panel opens, pre-filled with the template's own file name, in the folder above. Nothing is written if you cancel.

  3. The file is written

    The template JSON is saved to the path you picked, and the open diagram picks it up immediately: the template is applied to the running modeler, so there is nothing to reopen and nothing to restart.

  4. The configuration is updated, the first time

    When the project's penstock.yaml has no elementTemplates list yet, the new file becomes its first entry. A list that is already there is not changed.

For a connector that ships several templates, the card's install button takes every template of that connector you do not already have. That path asks for a folder rather than a file name, then warns that it will write one file per template into that folder and overwrite existing files with the same names, and waits for you to confirm. Each file is saved under the template's own file name; progress is shown on the connector's button. To take one template of such a connector on its own, open Details and install it from the list.

Templates already present are marked as installed and their install buttons are disabled. A catalogue template counts as present when an entry in elementTemplates ends in the same file name, or when a template already loaded for the diagram carries the same name.

Camunda 7, Operaton, CIB seven and Classic BPMN

Only the connector browser is gated on Camunda 8: under the other profiles the More menu has no Templates….

Loading is not gated the same way. The templates are read and handed to the editor whichever profile the diagram uses. The Camunda 7 modeler applies templates - it carries the same element template properties provider and template chooser as the Camunda 8 one - so Camunda 7 templates in .camunda/element-templates work there as well, and so do Operaton and CIB seven, which use that modeler. The Classic BPMN editor has no element template support at all, and templates handed to it are ignored.

In a terminal

penstock connectors lists Camunda's connector templates, and penstock connectors resolve <id> [version] prints one. It reads the same cache the browser fills, downloads from GitHub at most once a day, and works from the cache when the network is not there. --refresh asks GitHub for a newer release now. See Command line.

When a template does not appear

Check, in this order: that the diagram's engine profile is Camunda 8 or one of the Camunda 7 family rather than Classic BPMN, that the file is in a .camunda/element-templates folder at or above the diagram or under a path elementTemplates lists, relative to the project root, and that the file still exists there. penstock doctor reports a listed path that is missing. If all of that holds, look in the IDE log - a file that is too large or does not parse is skipped with a message naming the path.
