Validation with bpmnlint

bpmnlint answers whether a process is modelled correctly: an event with no outgoing flow, a gateway that splits without saying how. Penstock runs it without any setup, in the editor as you draw and in penstock check, with nothing to install and no paths to configure.

Which rules apply

Without a configuration the rules are bpmnlint's own recommended set, bpmnlint:recommended. A .bpmnlintrc in the project root replaces that set, and the editor and the command line both read it. To keep it somewhere else, name it with lint.configPath in penstock.yaml, relative to the project root; see Configuration.

A minimal .bpmnlintrc:

{
  "extends": ["bpmnlint:recommended"],
  "rules": {
    "label-required": "error",
    "no-implicit-split": "warn"
  }
}

In the diagram editor

The editor marks problems on the elements as you draw, with a marker on each element a rule reports. The linting button on the canvas turns the markers off and on; it starts on, and is hidden while token simulation is running, since the canvas is showing something else at that point.

The same findings are listed under Rules in the diagram check, beside the drawing problems. Each line gives the message, the element it is about and the rule's name, with warning after the name for a rule set to warn. Clicking a line scrolls to the element and selects it.

On the command line

penstock check runs the same rules as one section of its report, beside the drawing and, on Pro, the flow analysis. penstock check --only rules runs the rules alone. A rule set to error makes the run fail; a warning is reported as a note. See Command line.

penstock check --only rules .

In the IDE, Check in the context menu of the Penstock tool window runs penstock check on a file or folder and shows the report in the Run window. It runs only in a trusted project.

penstock lint still works in this release and says that it is now penstock check --only rules.

Custom rules

A custom rule comes from a bpmnlint-plugin-<name> package. Declare it in the project's package.json and run npm install: the command line reads plugins from the project's node_modules, with no installed bpmnlint needed.

The editor cannot load packages from node_modules. For a .bpmnlintrc that uses a plugin, build a bundle of the rules with bpmnlint-pack-config and name it with lint.clientBundlePath in penstock.yaml. Rebuild it whenever the rules change; the editor loads that bundle, not the .bpmnlintrc. Without it, the diagram check says The bpmnlint rules could not run and points at lint.clientBundlePath.

lint:
  configPath: .bpmnlintrc
  clientBundlePath: .bpmnlint/client.bundle.js
