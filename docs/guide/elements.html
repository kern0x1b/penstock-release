BPMN elements

The palette down the left of the canvas carries the elements most diagrams are built from. Everything else — every task type, every event, every gateway — is behind Create element at the foot of the palette, which is searchable and explains what each element is for.

The palette

Four tools and ten elements, in this order:

Hand toolPans the canvas without selecting anything.
Lasso toolRubber-band selection.
Space toolInserts or removes empty space, moving everything past the line you drag.
Global connect toolDraws a connection starting from any element.
Start eventWhere a process or a path begins.
Intermediate / boundary eventSomething the process waits for or emits part way through; dropped on the border of an activity it becomes a boundary event.
End eventWhere a path ends.
GatewayA branch or a join.
TaskA step of work.
Expanded sub-processA process drawn inside the diagram that contains it.
Data object referenceData that lives as long as the process instance.
Data store referenceData that outlives the instance.
Pool / participantAn organisation or system taking part in a collaboration.
GroupA visual box around elements; it carries no execution meaning.
Create elementOpens the catalogue below.

The catalogue

Type to filter, or open a group. The same catalogue appears from an element's context pad, where it appends the element you choose to the one you started from, already connected.

Tasks — atomic units of work in a process

TaskAn unspecified step, often used as a placeholder.
User taskWork that needs to be done by a person.
Service taskAutomated work carried out by a job worker or connector.
Business rule taskEvaluates a business rule, typically a DMN decision.
Script taskRuns a script. On Camunda 7 the script opens as a real editor tab — see Editing a diagram.

Gateways — route the flow

Exclusive gatewayRoutes the token down one path, based on data.
Parallel gatewaySplits the flow into parallel paths, or joins them.
Event-based gatewayFollows the path of whichever event occurs first.

Sub-processes — nested or reusable activities

Call activityCalls another process as a reusable subprocess.
TransactionA subprocess that completes as a whole, or is compensated.
Event sub-processA subprocess triggered by an event in its scope.
Sub-process, collapsedGroups elements into a subprocess, shown collapsed. Double-click to open it in its own view.
Sub-process, expandedGroups elements into a subprocess, drawn inline.
Ad-hoc sub-processActivities run in any order, any number of times. Collapsed or expanded.

Events — what a process reacts to or emits

Events are grouped by where they sit in the flow rather than by what they carry, because the same kind of trigger means different things in each position.

Start eventsWhere a process or path begins.
Intermediate catch eventsWait for something to happen before continuing.
Intermediate throw eventsEmit an event, then continue.
Boundary eventsReact to something while an activity is running. Interrupting ones cancel the activity; non-interrupting ones leave it running.
End eventsWhere a process path ends.

Inside each group are the triggers BPMN defines — message, timer, error, escalation, signal, compensation, conditional, link, terminate — restricted to the ones that are legal in that position.

Data

Data object referenceData created and used within a process instance.
Data store referenceData that persists beyond the process instance.

Participants

A pool stands for an organisation or a system. Two pools in one diagram make it a collaboration, and the only thing that may cross between them is a message flow. Lanes divide a pool by role or department and carry no execution meaning of their own.

Changing an element into another

Select an element and use the wrench on its context pad. The menu offers every element the selected one can legally become — a task to a service task, a start event to a message start event, an exclusive gateway to a parallel one — and the change keeps the connections, the name and the properties that still apply.

What each profile adds

The palette and the catalogue are the same in all three engine profiles: BPMN is BPMN. What changes is what the properties panel offers once an element is selected, and which namespace the editor writes into the file. See Engine profiles.
