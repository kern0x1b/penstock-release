Editing a diagram

The editor is bpmn-js running in a JCEF browser inside the IDE window. The modelling surface is the familiar one; what Penstock adds is the IDE around it — the system clipboard, script files that open as real editor tabs, and a diagram-level diff in the IDE's own diff window.

Canvas and palette

Which modeller is built depends on the engine profile. Camunda 7 and Camunda 8 get the matching camunda-bpmn-js modeller, which carries that platform's moddle extensions, its properties provider and its element template support; Penstock adds the element template create and append module to both, and create and append anything to Camunda 8. Classic BPMN gets plain bpmn-js with the standard properties panel and provider. All three load task resizing, token simulation and the minimap. The palette is bpmn-js's own — Penstock replaces nothing — extended by whichever create and append modules the profile loads.

Hovering an element for half a second shows a tooltip with its id, type, name and connected flows — plus the implementation, class or delegate expression on a service task, and the assignee and candidate users and groups on a user task. The right-click menu holds Reload, Undo, Redo, Copy, Paste, Delete and Export.

The properties panel

The canvas and the panel are two halves of a resizable split; the panel opens about 300 pixels wide. The properties panel toggle, an icon at the right edge of the toolbar that stays pressed while the panel is open, collapses it to zero width and restores it. While collapsed it is detached from the modeller entirely, so it does not keep re-rendering in the background, and is re-attached when reopened. Collapsing is remembered: selecting an element does not force the panel open again.

Editing scripts in an IDE tab

Under Camunda 7, script fields get a CodeMirror editor instead of a plain text area — Groovy highlighted as Groovy, everything else as JavaScript. It is installed into the Script and Condition groups and into the input mapping, output mapping, execution listener and task listener entries, so a script nested in a listener is edited like the task's own. Typing reaches the model 400 ms after you stop.

Below each editor is an Edit in new tab button. It hands the current text to the IDE, which opens it as an editor tab carrying the script format's extension — .groovy, or .js for JavaScript — so the IDE's own highlighting, completion and inspections apply. The file is in-memory only; nothing is written to disk. While that tab is open the in-panel editor is read-only, so there is one place to type. Every keystroke in that tab is pushed back to the in-panel editor, debounced by 100 ms, and reaches the model on the same 400 ms rule as typing in the panel. Close the tab and the in-panel editor becomes editable again; press the button again and the existing tab is focused.

From a delegate class to the class

Right-click a task that names a Java class — a Camunda 7 camunda:class, a delegate expression that unwraps to a fully qualified name, a listener that names one — and the menu offers Go to that class. It opens the file in the IDE, found by name and package in the project's own sources.

A class that lives in a dependency rather than in the project's sources is not found.

The XML tab

The diagram editor is registered ahead of the IDE's own editor, not in place of it, so the plain XML editor stays available as a second tab on the same file.

Edits round-trip in both directions. Every change on the canvas re-serialises the diagram and writes the whole file: the content goes to a temporary file beside the target, which is moved over it atomically and refreshed in the VFS. There is no save step; the XML tab shows the new content at once.

The other direction is watched rather than merged. Penstock tracks the file's modification stamp and ignores its own writes. When something else changes the file — the XML tab, a Git checkout, a formatter — the editor asks whether to reload. Reloading takes the external content and discards unsaved canvas edits; declining keeps you editing, and your next change overwrites the external one. Renames are handled silently.

Copy, paste, undo and redo

Undo and redo drive the modeller's command stack, covering every modelling operation in the order it happened. Copy and paste go through the IDE's own CopyPasteManager — the system clipboard — rather than a clipboard private to one diagram, which is what makes copying a pool out of one diagram and pasting it into another open diagram work. Paste from the toolbar or the context menu, having no mouse position to attach to, drops the elements at the centre of the view.

Minimap

Minimap, in the More menu, toggles the diagram-js-minimap overview.

Token simulation

Simulate switches the canvas into bpmn-js-token-simulation's simulation mode; the button stays highlighted until you switch it off. The module blocks dragging, the context pad, popup menus and direct editing, but not programmatic changes, so Penstock blocks the rest itself: Undo, Redo, Copy, Paste, Delete and Auto Layout refuse to run and say Stop Token Simulation before editing the diagram. Otherwise an edit made during what looks like a read-only preview would be written to the file like any other.

Export

Export opens a dialog with a live preview beside four choices: theme (Light, Dark, Dracula), schema (Default, or Sketchy, which draws the diagram hand-drawn in the Virgil font), format (SVG, PNG or PDF), and whether to paint the theme background behind the diagram or leave it transparent. Collapsed subprocesses get a fifth control, to export one of those instead.

SVG is written as rendered. PNG is rasterised at twice the diagram's size, capped at 8192 pixels on the longer side so large diagrams stay inside the browser's canvas limit. PDF is that PNG on a single A4 page, portrait or landscape by aspect ratio, scaled to fit under a heading. The IDE's save dialog then asks where to put it.

Comparing two versions of a diagram

Penstock registers a diff tool with the IDE, so any two-sided comparison where one side is a BPMN file — Compare with Revision, a commit in the Git log, a shelved change — is shown as two diagrams rather than two blocks of XML: Before on the left, After on the right, each read-only, with the palette and context pad hidden. The visual diff is part of Penstock Pro.

The comparison is semantic, not textual. Both revisions are parsed with bpmn-moddle and compared with bpmn-js-differ, which sorts elements into added, removed, changed, and changed in layout only. Each is outlined in its bucket's colour: removed on the Before side, added on the After side, changed on both.

The fourth bucket is the useful one. An element that only moved or was resized is marked in its own colour on the After side, apart from real changes, so a commit that ran auto layout reads as what it is rather than as every element having been edited.

Toolbar reference

Undo and Redo always sit on the toolbar, as icons. Every other action is in the More menu, the button marked with three dots, with its icon and its name, and the pin in each row puts it on the toolbar or takes it off.

Undo, RedoUndo or redo the last operation. Always on the toolbar.
Auto LayoutLays the diagram out in place. Pinned to start with. See Auto layout.
CheckOpens the diagram check. Pinned to start with. See Diagram check.
SimulateToken simulation. Pinned to start with.
Properties PanelCollapses or restores the properties panel. Pinned to start with, as an icon at the right edge.
DeployDeploys the diagram; the arrow beside it deploys to another profile or edits the connection. Pinned to start with, on the right. Camunda 7 and Camunda 8 only. See Deployment.
MinimapToggles the overview.
Copy, PasteTo and from the system clipboard.
Export…Opens the export dialog: theme, drawing style, format and background, with a preview.
Templates…The connector template browser. Camunda 8 only. See Element templates.
Sketchy DrawingDraws the diagram as if by hand. A personal choice; the file is not changed.

Check, Simulate, Minimap and Sketchy Drawing stay highlighted while active; Undo, Redo, Copy, Paste and Auto Layout are blocked while a simulation runs.

Deploy and Templates… are the only two that depend on the engine profile; under BPMN Classic neither appears. Which actions are pinned, and Sketchy Drawing, are kept in ~/.penstock/preferences.json, so they are the same in every IDE on the machine. The diagram always takes the IDE's theme.

Decisions (DMN)

A .dmn file opens in a decision editor in the same place: the requirements diagram, decision tables with their hit policy, typed inputs and outputs and a column for annotations, and literal and boxed expressions. The bar at the top switches between every decision in the file. Camunda's DMN extensions are read and kept, and the file is saved as you edit, the same as a diagram.

With Pro, Check in the bar compares the rules of every decision table: two rules of a Unique table that match the same input, which is an error at run time, and inputs no rule matches, each with the values. penstock check does the same for the .dmn files in a project.

Deploy in the bar sends the file to the engine with the same settings a diagram uses, and the Penstock tool window lists decision files beside the processes.

Forms

A Camunda Form (.form) opens in a form editor: the palette of fields on the left, the form in the middle and its properties on the right. It is saved as you edit and deployed with Deploy in the bar. A .form file of the IntelliJ GUI Designer is left to the GUI Designer.

With Pro, Check finds two fields writing one variable, or a field writing the path of a group — Tasklist refuses to open such a form — fields that write no variable, option lists that offer one value twice and inputs with no label. penstock check does the same for the forms in a project.
