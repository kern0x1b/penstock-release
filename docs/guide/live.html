Guide / Running

Live

Live shows what the engine is doing with your diagram right now: how many instances wait on each step, and which have an incident.

Free A deployment profile with an address

On this page

  • Steps
  • What you see
  • When the engine is asked
  • Common problems

Steps

  1. Deploy the process, so the engine has it. See Deployment.
  2. Press Live on the toolbar. A card called Live opens at the bottom right.
  3. Penstock asks the engine of the profile in force. The card's header shows the profile and the process version, for example prod · version 3.
  4. Look at the diagram. Badges on the shapes show how many instances wait there, and how many have an incident.
  5. Press Refresh to ask again. Press Close to put the badges away.

What you see

IncidentsEach incident with the step, and the engine's message. Click a line to select the step. Code opens the worker that runs the task, when Pro links code to the diagram.
WaitingEach step with instances waiting on it, and how many.
HoverThe hover card of an element says what waits on it.

Other messages: No instance is running on prod. and order-process is not deployed on prod. The last line of the card says which address was asked and when.

When the engine is asked

Only when you open Live or press Refresh. Never in the background. It works on Camunda 7, Operaton and CIB seven, and on Camunda 8.8 and later. The request is made with the profile's credentials. See Security and privacy.

Common problems

The card says to set up the deployment profile.
The profile in force has no address. Press the arrow next to Deploy and choose Connection…. Or set deployment.url.
"The engine refused the question (403)".
The profile's user may not read process instances. Use a user that may.
"is not deployed on …".
Deploy the process to that profile first.
The numbers look old.
Press Refresh. Live does not update by itself.
