Diagram check

The check reads the diagram the way a person does and lists what is wrong with the drawing: shapes on top of each other, a connection that does not reach the shape it connects, an element that has drifted out of its pool. It is the same set of measures the auto layout engine is held to, run against the diagram you have open.

What it is not

This is not bpmnlint. bpmnlint answers whether the process is modelled correctly — an event with no outgoing flow, a gateway with no condition. The check answers whether the diagram can be read: it knows nothing about process semantics and never looks at an attribute. Both can be useful on the same file, and they never report the same thing.

Problems

The first group is defects that make a diagram wrong rather than untidy. A reader cannot tell what a diagram means when two shapes sit on top of each other, so these are listed expanded and counted in the header.

Shapes sit on top of each otherTwo shapes overlap. Neither can be read, and a click lands on whichever happens to be on top.
Connection runs through a shapeA line crosses the interior of a shape it does not connect, so it reads as though it stops there.
Connection does not reach the shape it connectsThe line ends short of, or past, the element it is attached to. Usually the result of moving a shape without the line following it.
Element outside the container it belongs toAn element is drawn outside the pool, lane or sub-process that owns it in the model, or inside one that does not.
Boundary event is off its hostA boundary event is no longer on the border of the activity it is attached to.
Labels cover each otherTwo labels overlap, so at least one of them cannot be read.
Connection doubles back along itselfA route leaves a point, goes past it and comes back along the same line. It reads as a single line drawn twice.

Readability

The second group is collapsed, and deliberately so: a diagram drawn by hand always has some of these, and a count of zero is not the goal. They are worth reading when a diagram is hard to follow and you want to know why.

Connections crossTwo lines cross each other.
Connections run along the same lineTwo lines run parallel close enough to be read as one.
Connection runs along the border of a shapeA line runs beside a shape's edge for long enough to look attached to it.
Connection crosses a labelA line is drawn over a label that belongs to something else.
Connection takes a long way roundThe route is more than twice the distance between the two shapes it connects.
Connection sidesteps for no reasonA short jog between two parallel runs with nothing in the way of the straight line.
Label sits far from what it namesA label has drifted away from its shape or its own line.
Annotation sits far from what it describesA text annotation is joined to its element by an unusually long association.
Connection is not drawn at right anglesA segment runs diagonally rather than horizontally or vertically.

Working through the list

While the panel is open, every element a problem is about carries a dashed outline on the canvas, so the trouble is visible without reading a single line of the list. Moving the pointer down the list outlines the one under the pointer. Clicking a line scrolls the canvas to it, selects it and outlines it in red — the selection is a normal one, so the properties panel and the context pad are right there and the next edit is one click away.

The list refreshes as you edit, a few hundred milliseconds after the diagram settles, and Recheck forces a fresh pass. Close puts the outlines away.

Fixing a whole diagram at once

Auto layout is the other half of this. The check measures a diagram against a set of rules; auto layout draws a diagram that satisfies them. On a diagram that has drifted far enough to collect a long list, laying it out again is usually faster than working down the list by hand.

What it cannot see

Three of the engine's measures need the file rather than the canvas — a connection declared in the XML that was never drawn, one drawn with an end missing, and a comparison of what the diagram meant before an operation against what it means after. The panel leaves those out rather than reporting them as passing.
