Guide / Project setup

The Penstock tool window

The Penstock tool window shows your project as a model: processes, the workers they need, messages, decisions and forms, not just files.

Free Some parts need Pro

On this page

  • Open it
  • What the tree shows
  • The toolbar
  • Right-click actions
  • Common problems

Open it

  1. Click Penstock in the tool window bar on the left of the IDE.
  2. The tree lists your project. Double-click a node to open it. On a diagram element, it selects the element on the canvas.
  3. Right-click a node for its actions. The menu always starts with Open, and ends with the command-line actions.
  4. Type to search the tree.

When the project has no diagrams the tree says No diagrams in this project and offers Start from an example. See The example project.

What the tree shows

NodeWhat is under it
ProcessesEvery process, with the processes it calls and is called by. With Pro: its tests and how much of it they cover.
Tests ProEvery process test, by class, with what each covers. You can run or debug any of them, a class, or all.
WorkersWhat each task needs to run: a job type, topic, class or bean. Right-click a worker for Go to Implementation and Find Usages in Code. A worker nothing implements is marked. Check Workers on… asks the engine whether anything picks the work up. See Check Workers.
VariablesEvery process variable, where it is set and read, and a warning for one that is read but never set, or one that is set a letter away: set as 'approved'?
MessagesEvery message, with who catches and who throws it.
ErrorsEvery error code, where it is caught and where it is thrown. Marks a code that is thrown but never caught, and an error event nothing throws.
DecisionsEvery decision, and the tasks that call it. A decision the project does not have is marked not in project.
FormsEvery form, and the tasks that use it. A form the project does not have is marked not in project.
DeploymentEach profile with its address and the last deploy. Right-click a profile and press Deploy to send every diagram to it, after a confirmation.
FilesThe files, in folders.
DebugOnly while the debugger is stopped in a worker. It shows the task the debugger is in.
Migrate to Camunda 8Only in a Camunda 7 project. See Camunda 7 to 8.
CodeWithout Pro, a single line that says what Pro adds, and Buy or Sign In….

The Workers, Variables, Messages, Errors and code links parts need Pro for the links to your source code. Without Pro, the model of your diagrams is still shown.

The toolbar

Run PenstockA menu of command-line actions: Check, Paths, Tests, Code, Docs, Format, Diff Since…, Export… and Doctor. Each runs penstock on the selected file or folder and shows the output in the Run window. It uses the project's penstockw when there is one. It runs only in a trusted project. Paths, Tests, Code and Docs need Pro.
Reload from DiskRe-reads the project from disk. The tree also refreshes by itself when a file changes.
Run All Process TestsRuns every process test. Shown when process tests exist. Pro.
Group by FilesTurns the tree round: file by file, with each process's elements and what runs them.
Show FoldersSwitches between a tree of folders and a flat list.
Open penstock.yamlOpens the project's configuration, or creates it when there is none.

Whether the view is grouped by files, and whether it shows folders, are kept in ~/.penstock/preferences.json.

Right-click actions

  • Open opens the file, or selects the element.
  • Copy ID copies the process id, decision id, job type or other name to the clipboard.
  • Find Usages in Code lists the code that names it. Pro.
  • Go to Implementation opens the method or class that runs a worker. Pro.
  • Run Tests and Debug Tests. Pro.
  • Deploy sends a file or a process to its profile.

Common problems

The tree is empty.
The project has no .bpmn, .dmn or .form files that Penstock can see. Build folders such as node_modules, build, target, out and dist are skipped. Press Reload from Disk.
The Run Penstock actions do nothing, or an error says the project is not trusted.
Trust the project. The command line runs code from your project's node_modules and hooks, so it needs trust.
The first command is slow.
Without a penstockw in the project, Penstock runs npx @penstock/cli and downloads the command line the first time. penstock init adds the wrapper, which pins a version.
There is no Go to Implementation.
Code links are a Pro feature, and nothing in the project implements this worker.
