Code links

Code links tie your diagrams to the code that runs them, so you can jump between a task and its worker, and find out when they disagree.

Pro Team in a pipeline. Going from a Camunda 7 delegate to its class is free.

What it is

A diagram says "this task needs the job type charge-card". Your code has a worker for charge-card. Code links know both, and connect them. They read Java, Kotlin, JavaScript, TypeScript, Python, Go and C# by reading the text, so a worker in another language or another repository still counts.

Free and Pro

Going from a Camunda 7 task to its Java class or Spring bean is free. See Editing a diagram. Everything below needs Pro. Without Pro, Penstock keeps only class and bean links, and an action that needs the rest says what it gives and offers to buy or sign in.

From code to diagram

A process id, element id, job type, topic, message name or decision id in a Java or Kotlin string is a link.

  1. Hold Cmd (or Ctrl) and click the string, or use Go to Declaration.
  2. The diagram opens and the element is selected.
  • Completion offers the ids where Camunda expects them: starting a process, asserting in a test (isWaitingAt, hasPassed, hasCompletedElements, byId and others), @JobWorker and external task subscriptions, correlating a message, evaluating a decision.
  • An id that no diagram has is marked.
  • A gutter icon beside such a string, a JavaDelegate or bean that diagrams name, and a @JobWorker method whose name is the job type, jumps to the tasks that use it.
  • A @JobWorker without a type takes the method name as the job type. That is marked, because renaming the method stops the worker. A quick fix writes the type into the annotation.

From diagram to code

  • Hover an element to see what runs it, the tests that name it, how often the rest of the code does, the variables it sets and reads, and whether tests reach it.
  • Go to Implementation is in an element's menu. It opens that method, not just the file.
  • Find Usages in Code, from an element's menu or the tool window, lists the code that names the element, its process, the job type, class or bean it runs, its message or its decision. That is the worker, the tests, and the code that starts it.
  • Code Vision above a worker, delegate or bean says which tasks it runs and how many tests reach it. Above a test it says how much of each process it covers. A click opens the diagram at the element.

Variables

Penstock reads where each process variable is set and read: input and output mappings, conditions, FEEL and JUEL expressions, result variables, form fields, message correlation keys, multi-instance collections, call activity in and out. In code, getVariable, setVariable, variable, @Variable and the test assertions complete the names the diagrams use and link back to the elements. A variable that is read but never set is marked. When a name is a letter away from a known one, Penstock asks set as 'approved'?.

Error codes

The code in new BpmnError("..."), handleBpmnError(task, "..."), an error command's errorCode("...") or CamundaError.bpmnError("...") opens the error event that catches it. A code no error event catches is marked. The tool window lists every error code with where it is caught and thrown, and marks a code thrown that nothing catches, and an error event nothing throws.

Check the diagram against the code

$ penstock code .
3 source file(s), 1 diagram(s), 4 reference(s) from diagrams to code

Every task the diagrams hand to code has something in the code to run it.

In the IDE, the check card has a Code section, and the tool window has Run Penstock | Code. It reports:

FindingRule
Nothing in the code runs a stepcode/missing-implementation
No worker handles a job typecode/no-worker
No external task worker subscribes to a topiccode/no-topic-worker
A class named in the diagram is not in the projectcode/class-missing
No Spring bean has the name a diagram usescode/bean-missing
A call activity calls a process no diagram definescode/unknown-process
A business rule task calls a decision no file definescode/unknown-decision
A user task shows a form no file definescode/unknown-form
A worker for a job type no diagram usescode/unused-worker
A variable is read, but only a similar one is setcode/variable-typo
Nothing throws the error a step catchescode/never-thrown

Names are matched exactly. A name that differs only by case, such as charge-Card against charge-card, is pointed out, because Camunda matches names exactly. Connector job types such as io.camunda:http-json:1 and job types set by an expression are understood and left alone. Job types of Camunda 8 execution and task listeners count as workers. The full list is in Every rule.

Other repositories

If your workers live in another repository, name it in penstock.yaml:

linked:
  - ../order-workers
  - ../shared-delegates

Paths are relative to the project root. Their diagrams, workers, delegates and beans are read with this project's. A path that is not checked out is skipped. penstock code reads them too.

The debugger

When the debugger stops in a job worker, an external task handler, a JavaDelegate or a task listener, the diagram marks the task it is running for, with the process instance. On Camunda 7 it marks the other active elements of that instance too. The tool window lists the same under Debug. The marks go when the program resumes.

What you see

  • A string that names a job type, topic, message or process is a link. A gutter icon sits beside it.
  • Hovering an element shows what runs it. Right-clicking it offers Go to Implementation.
  • In the tool window a worker that nothing implements says no implementation and carries a warning.

Common problems

No links appear.
Code links need Pro. The tool window shows a Code line with Buy or Sign In….
A worker in another repository is reported as missing.
Add that repository to linked in penstock.yaml.
A worker I know exists is not found.
Penstock reads the text of Java, Kotlin, Groovy, Scala, Python, JavaScript, TypeScript, Go and C# files. It skips node_modules, build, target, out, dist and .git. Generated code in those folders is not read.
