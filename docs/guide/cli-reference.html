Options that many commands share

--profile <name>Use this profile, as PENSTOCK_PROFILE would. See Profiles.
--format text|json|sarif|github|mdHow check, paths, show, docs and migrate report themselves.
--out <dir>, -oWhere a command puts what it writes. For share and import, -o is the file.
--helpPrint the help and stop.
--versionPrint the version.

init

Set up a project. penstock init [path]

  1. Writes penstock.yaml with the engine guessed from your diagrams. If a file exists, it is kept.
  2. Adds penstock.local.yaml to .gitignore.
  3. Installs the wrapper: penstockw, penstockw.cmd, and the properties file.
--example camunda-8|camunda-7Write a small runnable project into an empty folder. See The example project.
--ci github|gitea|forgejo|gitlab|bitbucket|azureAlso write a pipeline, for the licence on this machine. See Pipelines, reports and the bot.
--hooksInstall a pre-commit hook. It formats and checks the diagrams a commit carries. It lives in .git/hooks, so it is yours. Delete the file to stop it. It uses check --baseline, which needs Pro.

doctor

Find out why something does not work. penstock doctor [path]

$ penstock doctor
node        v26.10.0
root        /private/tmp/pex
config      penstock.yaml
engine      camunda-8
profiles    (none)
deployment  http://localhost:8080/v2 - answered 404

It prints the Node version, the project root, which configuration files apply, the engine, the profiles (a star marks the one in force), the rules file and element template paths (marked missing when they are not there), and whether the deployment address answers (with a 4 second timeout). Exit code 1 when something is missing. --format json prints all the settings that apply after every layer.

check

Everything wrong with the diagrams. penstock check [paths]

$ penstock check .
ok    src/main/resources/approve-order.form
fail  src/main/resources/order-process.bpmn
        OVERLAP: approve_order <-> charge_card
        note bpmnlint/no-overlapping-elements: Element overlaps with other element (approve_order)
ok    src/main/resources/shipping-method.dmn

Checks .bpmn, .dmn and .form files in three sections: drawing, rules (bpmnlint) and flow (Pro). Only errors fail the command.

--only drawing,rules,flowRun part of it. --only flow needs Pro.
--format json|sarif|githubMachine output with rule ids and their page. SARIF and GitHub annotations need Pro, and Team in a pipeline.
--baselineFail only on findings the baseline does not accept. Needs Pro.
--update-baselineWrite the current findings to penstock-baseline.json. Commit it. After an upgrade, refresh it.

See Diagram check, Validation and Flow analysis. Hooks: preCheck and postCheck.

migrate

Camunda 7 to Camunda 8. penstock migrate [analyze|convert|report] [paths]

Full description on Camunda 7 to 8. Options: --target 8.5..8.9, --dry-run, --out <dir>, --fail-on error|warning, --verbose, --format text|json|sarif|github, --baseline, --update-baseline. convert needs Pro, and Team in a pipeline. convert writes over your files unless you give --out.

code

Compare diagrams with code. penstock code [paths] Pro

Reports a job type, topic, class or bean that nothing runs, a called process no diagram defines, and a worker no diagram uses, each with file and line. Reads the repositories in linked. --format json for a tool. See Code links.

paths

List every way through each process. penstock paths [paths] Pro

--format md writes a checklist for a test plan. --format json is for tools. See Process tests and coverage.

tests

Write a JUnit test for every way through each process. penstock tests [paths] Pro

--out <dir> the source folder. --package <name> the package. The command names the test dependencies your build lacks. See Process tests and coverage.

test-cases

Run test cases on an engine, step by step, with mocks. penstock test-cases [paths] Pro

--generateWrite test cases from the ways through each process.
--junitWrite a Camunda Process Test class that runs the same files under JUnit.
--junit-xml <file>Write a JUnit XML report.
--teamcityPrint TeamCity service messages.
--timeout <seconds>How long one step may take. Default 30.

See Runs and test cases.

layout

Lay the diagrams out. penstock layout [paths] Pro

$ penstock layout .
would change src/main/resources/order-process.bpmn

Auto layout always reflows, so a difference here is expected; pass --write to take it.

--write saves the result. Without it nothing is changed. Hooks: preLayout, postLayout. See Auto layout.

fmt

Format the XML the way the editor saves it, so a renamed task is a one-line diff. penstock fmt [paths]

--write saves. Without it, it lists each file as same or would rewrite, and exits with 1 if any file would change. So it also works as a check in a pipeline.

diff

What changed.

penstock diff before.bpmn after.bpmn     # two files
penstock diff main                       # working tree against a branch, tag or commit
penstock diff HEAD~3 src/orders          # limit to some paths
penstock diff main --images              # pictures with changes coloured (Pro)
$ penstock diff HEAD
src/main/resources/order-process.bpmn
  changed  ServiceTask "Charge the card" charge_card (name)

It lists added, removed and changed elements by name, and says only the drawing moved when that is all. Without a reference it compares against HEAD~1. --images-dir and --out choose where the pictures go (default .penstock/images).

export

Pictures of the diagrams. penstock export [paths] --out <dir>

SVG, drawn by Penstock from the coordinates. No browser needed. --format png needs puppeteer in the project. See Export.

share

One HTML file to send. penstock share <file> [-o out.html]

Takes one .bpmn, .dmn or .form file. Opens offline in any browser. See Share as HTML.

import

Turn a draw.io, Visio, Signavio or Bizagi diagram into BPMN 2.0. penstock import <file> [-o out.bpmn] [--force]

Prints what was not imported, what was guessed and what was not carried over. --format json for a tool. See Import a diagram.

docs

Write documentation for every process, decision file and form. penstock docs [paths] --out <dir> Pro

$ penstock docs . --out docs-out
wrote docs-out/approve-order.html
wrote docs-out/order-process.html
wrote docs-out/shipping-method.html
wrote docs-out/index.html

3 diagram(s) documented.

A page for each process: its picture, steps with what runs them and who, decisions and conditions, events, the data each step sets and reads, and whether it runs to its end. A page for each .dmn file with every decision's rules as a table, its hit policy in words and the table check. A page for each form with the variable every field writes. HTML by default, --format md for a wiki.

report

One Markdown comment for a pull request. penstock report [path] --base origin/main Pro

$ penstock report . --base HEAD
wrote penstock-report.md
--base <ref>What to compare against. Default origin/main.
--out <file>The Markdown file. Default penstock-report.md.
--images-dir <dir>Where the pictures go. Default .penstock/images.
--image-base <url>Where the pictures will be served from, so the comment shows them.
--images-link <url>Where to find them instead, when they cannot be shown inline.

The report holds the check, what changed and pictures with the changes outlined. It needs a Git repository. See Pipelines, reports and the bot.

bot

Answer in a pull or merge request, from the CI run it is in. penstock bot [path] Team in a pipeline

--stage draw|post draws the pictures now and posts later, when the pictures are uploaded between. init --ci writes the pipeline. See Pipelines, reports and the bot.

deploy

Send processes, decisions and forms to the engine. penstock deploy [paths]

$ penstock deploy . --dry-run
would send 3 file(s) to http://localhost:8080/v2/deployments as "order-example"
      src/main/resources/approve-order.form
      src/main/resources/order-process.bpmn
      src/main/resources/shipping-method.dmn
--dry-runSay where, and send nothing. Try it first in a new pipeline.
--waitAsk the engine until it shows the definitions. "Deployed" and "running" are not the same claim. Prints live order-process v3.
--profile <name>Choose the environment.

Files are grouped by the target each folder asks for. A file with no deployment.url is skipped. Secrets: PENSTOCK_PASSWORD, PENSTOCK_CLIENT_SECRET, PENSTOCK_TOKEN. Any PENSTOCK_* variable that matches a setting overrides it for the run. Hooks: preDeploy, postDeploy. See Deployment.

show

List a diagram's elements, flows and properties. penstock show <file>

$ penstock show order-process.bpmn
order-process.bpmn  (camunda-8)

StartEvent             order_received "Order received"
ServiceTask            charge_card "Charge card"
                         jobType = charge-card
SequenceFlow           Flow_2  approve_order -> charge_card

--format json is for tools. The ids it prints are the ones edit refers to.

edit

Change a diagram the way the editor would. penstock edit <file> <change> Pro

penstock edit orders.bpmn add service-task --after Task_check --name "Reserve stock" --set jobType=reserve-stock
penstock edit orders.bpmn connect Gateway_stock Task_notify --condition "=not(inStock)"
penstock edit orders.bpmn set Task_notify --set assignee=support --input customer==order.customer
penstock edit orders.bpmn remove Task_legacy

A new element is placed and connected by the editor's own modelling, gets an id from your conventions, and carries only properties your engine knows. After an edit the diagram is read back and checked. An edit that would break the drawing (shapes on top of each other, a flow through a shape, a flow torn from its element) is not written. A crossing is reported but allowed.

--dry-runShow the result without writing.
--ops '<json>', --ops-file <file>The same changes as JSON. This is the contract. Several operations apply together or not at all.
--schemaPrint the JSON contract for the file's engine. Free. An unknown operation, field or property is refused.
--forceWrite even when the edit would break the drawing.

license

Buy, sign in, status. penstock license [status|key|activate <key>], license buy [pro|team], license login [email], license logout. See Buying and signing in.

mcp

Serve the project's diagrams to an AI agent over MCP. penstock mcp, penstock mcp --config. See The MCP server.

connectors

List Camunda's connector templates, or print one.

penstock connectors                              # list the current templates
penstock connectors resolve <id> [version]      # print one template as JSON
penstock connectors --refresh                    # ask GitHub for a newer release now

The templates are downloaded from GitHub at most once a day and cached in ~/.penstock/connectors/. See Element templates.

update

Move the project's wrapper to a version. penstock update [version]

The latest version by default. --distribution <spec> chooses where to get Penstock from: a tarball or a registry spec. See Command line.

What you see

  • Most commands print one line for each file. A line starts with a word: ok, fail, wrote, same, would change or sent.
  • Findings are indented under their file.
  • The exit code says the outcome. See Command line.

Common problems

An option is ignored.
Check that it belongs to that command. For example --write is for layout and fmt, and --wait for deploy.
"Unknown command".
Run penstock help. Some old names are still accepted and say what replaces them.
The command says the project is not a Git repository.
diff <ref> and report compare against Git history. Run them inside a checkout.
