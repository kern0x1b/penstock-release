Auto layout

Auto layout is not a tidier. It throws away the positions in the file and draws the diagram again from the process model, so a badly drawn diagram comes back readable and a well drawn one comes back arranged by the engine's rules rather than yours.

What it does to a diagram

Every shape is placed from scratch. The engine reads the sequence flows and works out, for each element, the longest chain of flows that reaches it, counting from the elements that have nothing flowing into them. Each chain length gets its own column. Columns run left to right, so the flow reads left to right no matter which direction it was drawn in. Elements that share a column are spread into rows, and the row order is chosen to keep the connections between columns from crossing each other. A sub-process or a pool is laid out before the element that holds it, so a container is sized by what is inside it rather than the other way round.

That first arrangement is then made legal. Shapes are pushed apart until none of them overlaps, each one moving as little as possible from where it was put, and every container is resized to fit the contents it ended up with — including shrinking, when the contents now need less room than the box they were drawn in.

Pools that exchange messages are stacked one above another, in an order taken from the message flows between them, so that pools that talk end up near each other. A set of pools with no messages to the rest forms a block of its own, and the blocks are packed into columns across the page rather than into one tall stack. The gap between two pools in a stack is sized by how many of the message flows between those two pools have to run side by side in it.

Connections are routed last, around the shapes rather than through them, with every segment horizontal or vertical. Labels and text annotations are placed after that, against the routes that were actually drawn: a label is moved to a spot that no connection crosses whenever one can be found, and settles for a crossed spot only when none can, and a note is anchored to the final position of the thing it comments on.

The engine builds several arrangements for the same diagram — different pool orders, different rules for turning a message flow, different routing preferences — measures each one, and keeps the one that measures best. Crossings, lines lying on top of one another, bends and drawing area all count against a candidate.

What it will not do

These are the properties the engine holds to. Each one is checked on every diagram in the test corpus, and a layout that breaks one of them fails the test suite:

Overlapping shapesNo two shapes overlap, leaving aside a container and what it holds, and a boundary event on its host.
A connection through a shapeNo route may cross a shape that is not one of its own endpoints or a container holding one.
A detached connectionBoth ends of every connection stay on the element they belong to.
An element outside its pool or laneNothing leaves the participant, lane or sub-process it belongs to, and nothing wanders into one it does not.
A boundary event off its hostAn attached event stays on the border of the task it is attached to.
A diagonal connectionEvery segment of every route is horizontal or vertical.
A connection doubling backNo route overshoots and comes back along itself.
A label over another labelLabels do not land on each other or on a shape they do not belong to.
A change to what the diagram meansNo element changes parent and no connection changes source or target. Nothing is added, and nothing is dropped apart from the duplicate connection described below.

The corpus is 88 real diagrams, hand-drawn ones included. Every property above is required to hold on all of them, and the remaining measures — crossings, bends, route length, drawing area and the rest — may not exceed a figure recorded per diagram, with a two per cent margin on route length and drawing area, so a change that improves one diagram cannot quietly make another worse.

One thing is removed rather than moved. If the file contains two connections of the same type with the same source and the same target, the second one is deleted before the layout runs.

Running it

Auto layout is part of Penstock Pro. The diagram editor's toolbar has an Auto Layout button, which lays out the open diagram at once. A message follows, with Undo in it: the change goes through the editor's command stack like any other edit, so that button, or Undo in the toolbar, takes it back. There is no save step: the new positions are written to the file as soon as they land on the canvas, the same as any other edit. To compare the result with what was saved before, use the diagram diff described under Editing a diagram.

In a terminal, penstock layout lays the diagrams out and says what would change; --write saves the result. See Command line.

Spacing

Spacing is not a setting. The engine is tuned to its own spacing, and a few pixels either way made its layouts measurably worse, so layout in penstock.yaml and .bpmnlayoutrc are no longer read.

What it trades away

The guarantees above are absolute, and the things a reader notices next are not. Keeping every route out of every shape costs crossings, and it costs length: a message flow between two pools that are not neighbours in the stack has to travel around the pools in between, and that route can be much longer than the distance between its two ends. People drawing by hand solve this by putting the two communicating tasks directly above one another and dropping a short line between them. The engine does not, because holding a column in one pool to suit a partner in another costs more room and more crossings than the shorter line saves.

So a diagram you have arranged by hand may still read better in places than the one auto layout gives back, particularly a collaboration with several pools talking to each other. Auto layout is worth reaching for on a diagram you did not draw, on one that has been edited until it is unreadable, and on generated output. On a drawing you have already tuned, look at the result before you go on, and take it back with Undo if it reads worse.
