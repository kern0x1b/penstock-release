Camunda 7 to Camunda 8

Penstock reads a Camunda 7 diagram, an Operaton one or a CIB seven one, and says what Camunda 8 will not take. It can then convert it, showing you the diagram before and the diagram after before anything is written, and write the job workers the converted process needs beside the code they came from.

What is free and what is not

Finding out what does not carry over, and the report you hand to somebody else, are free. Converting is Penstock Pro, and Team in a pipeline, because it writes files and reads the project's code. See Plans and licence.

Finding out what does not carry over

There are three places to look, and they answer the same question.

Migrate to Camunda 8 on the toolbarOn a Camunda 7, Operaton or CIB seven diagram. It can be unpinned into the More menu. The section of the same name in the check card does the same thing.
Migrate to Camunda 8 in the tool windowA root of its own, listing every diagram in the project with its own result. It sits after Deployment and Files, and only when at least one diagram in the project is Camunda 7, Operaton or CIB seven.
penstock migrateEvery diagram in a folder, in a terminal or a pipeline. See Command line.

Each diagram, each decision and each form is reported on its own: what does not carry over, why, what to do about it, and who does it. A thing Penstock can convert exactly is offered two ways - convert it, or convert it and ask you to review the result - and a thing it cannot is left marked on its own element, for you to do.

The report

The result is a report you can hand over: Markdown, or one self-contained HTML page that opens offline. It is free, and it is the same report penstock migrate report writes. It lists every diagram, decision and form with what does not carry over, why, and what to do, so it can go into a ticket or a review.

Converting

Convert shows the diagram as it is on the left and the converted diagram on the right, in the visual diagram diff, with each diagram centred in its own pane under a single title. Nothing is written until you press Convert.

The Camunda 8 files go into a folder of their own, camunda-8 next to the folder the Camunda 7 files are in. The preview shows where, and you can change it there or pass --out. The converted folder gets a penstock.yaml of its own that says engine: camunda-8, so the Camunda 7 files are left exactly as they are and both engines keep working side by side. Converting into a folder that already holds converted files is not a dead end: the preview offers Replace the files in <folder>, with a warning when that folder is not under version control, and overwrites only when the box is ticked.

What cannot be converted exactly

It stays in the file, marked with a conversion:message attribute that the Camunda Modeler reads too, and it stays a finding in the check, so it does not get lost. A JUEL expression becomes FEEL only where the result is the same; where it is not, the refusal says why. Generated forms are written beside the diagram and never over a form that is already there.

Job workers from your delegates

Pro, and Team in a pipeline. Every Java delegate, external task handler and listener is followed to its source and to what it becomes. Beside it, Penstock writes a job worker skeleton in Spring, Node or Python, built from the variables that code reads and writes and the BPMN errors it throws. An existing file is never overwritten; the skeleton goes beside it under a name that is free.

In a terminal

penstock migrate analyze  .        what does not carry over
penstock migrate convert  .        write the Camunda 8 files (Pro)
penstock migrate report   . -o migration.html
--format text|json|sarif|githubHow the result is reported. SARIF and GitHub annotations need what they need for check, and they cover the migration findings too.
--fail-on warningWhat makes the exit code 1. An error does by default.
--baselineFails only on what is new since the baseline. Refresh it with --update-baseline.
--target 8.5 to 8.9The Camunda 8 version to convert for. 8.8 by default.
--dry-runSays what would be written and writes nothing.
--out <dir>Where the Camunda 8 files go, for convert.
--verboseLists and annotates what only carries over as it is.

The exit code follows the same rule as check. See Command line.
