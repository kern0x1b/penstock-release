BPMN diagrams, in the IDE you already use.

Penstock opens .bpmn and .bpmn20.xml files in a visual modeler inside JetBrains IDEs, right next to the raw XML. Process models stay in the project and in version control, so they are reviewed the same way as code.

Install from JetBrains Marketplace Any JetBrains IDE from 2025.2 · 30-day trial

What it does

Three modeling profiles

Classic BPMN 2.0, Camunda 7 and Camunda 8, chosen per project. The palette and the properties panel follow the profile.

Properties panel

Edit element properties, including the Camunda extension attributes, without leaving the diagram.

Inline scripts as real files

Groovy and JavaScript inside a script task open as an IDE tab with syntax highlighting and completion, and are written back into the diagram as you type. Camunda 7.

Element templates

Load Camunda 8 connector templates from the project, or pick them from the built-in template browser.

Deployment

Deploy the open diagram to Camunda 7 REST or Camunda 8, with basic auth or OAuth 2.0. Credentials go to the IDE password safe, never to a project file.

Validation

bpmnlint runs against the project’s own .bpmnlintrc and reports errors and warnings on the diagram itself.

Auto layout

Reformats a diagram you already have — separates overlapping elements, aligns sequence flows and routes connections orthogonally — and shows the result before applying it.

Token simulation

Step a token through the process to check that the flow behaves the way the model says it does.

Export and navigation

Export to SVG, PNG and PDF. A tool window lists every BPMN file in the project as a tree.

Getting started

  1. Open a .bpmn file

    It opens in the diagram editor. The editor tabs at the bottom switch to the raw XML and back, so nothing is hidden from you.

  2. Choose the engine

    You are asked once per project, and can change it later in Settings | Tools | Penstock.

  3. Add connector templates, if you are on Camunda 8

    Point the same settings page at template files or folders in the project, or install them from the built-in browser.

Validation with bpmnlint

Validation stays off until all three paths are set in Settings | Tools | Penstock: the bpmnlint binary, the .bpmnlintrc configuration and the client.bundle.js browser bundle. A minimal configuration in the project root: 

{
  "extends": ["bpmnlint:recommended"],
  "rules": {
    "label-required": "error",
    "no-implicit-split": "warn"
  }
}

Custom rules come from a bpmnlint-plugin-{name} package installed next to the .bpmnlintrc: declare it in package.json and run npm install. The editor re-lints the diagram as it is opened and changed; a command-line run over a file needs the project to be trusted first.
