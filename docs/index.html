Your process diagrams, in the IDE you already use.

Penstock opens .bpmn, .dmn and .form files in visual editors inside JetBrains IDEs, right next to the raw XML. Process models stay in the project and in version control, so they are reviewed the same way as code.

What it does

Five modelling profiles

Classic BPMN 2.0, Camunda 7, Camunda 8, Operaton and CIB seven, chosen per project or per folder. The palette and the properties panel follow the profile.

A toolbar you arrange

Every action is in one searchable palette, in sections, with a pin that puts it on the toolbar or takes it off. The same actions are in the IDE's Find Action and Keymap under Tools | Penstock.

A sidebar for each editor

Properties, Scenarios, Problems, Monitor and Code beside a diagram; Properties and Preview beside a form. Each tab keeps its place while you look at another one.

Check that explains itself

The card over the canvas and the Problems tab list what is wrong with the drawing, how the process runs, the modelling rules and what the engine can run. Every check has an id, a line on why it matters and a line on how to fix it.

Properties panel

Edit element properties, including the Camunda extension attributes, without leaving the diagram. Groovy and JavaScript inside a script task open as an IDE tab with syntax highlighting and completion, and are written back as you type. Camunda 7.

Element templates

Load connector templates from the project - a .camunda/element-templates folder is found without setup - or pick them from the connector browser, whose catalogue is downloaded from GitHub on demand and cached for you.

Deployment

Deploy the open diagram, decision or form to Camunda 7, Camunda 8, Operaton or CIB seven in one click and one popover, to the profile penstock.yaml puts in force, with basic auth or OAuth 2.0. Credentials go to the IDE password safe, never to a project file.

Validation

bpmnlint runs without any setup, with its recommended rules or the project's own .bpmnlintrc, and marks errors and warnings on the diagram itself. Engine compatibility rules ask what your Camunda version can actually run.

Camunda 7 to Camunda 8

See what does not carry over, why, and who does it. Convert a diagram with the visual diff before anything is written, and start job workers from your Java delegates. The analysis and the report are free; converting is Pro.

Scenarios and tests

Plan every way through a process over the diagram, with the values each step needs, and run the test cases against a local engine with mocks, seeing on the diagram what every step received and changed. Pro.

Linking a diagram to its code

From a step to the worker that runs it and back, usages, Code Vision, variables and error codes across both, tests run from the diagram, coverage on it, and what the engine is doing right now. Pro.

Auto layout

Reflows a tangled diagram into a readable left-to-right flow, in one click, with Undo in the bar that follows. Pro.

Token simulation

Step a token through the process to check that the flow behaves the way the model says it does.

Sharing and importing

Send somebody one HTML file that opens offline in any browser, with the documentation of each element. Bring a diagram in from draw.io, Visio, Signavio or Bizagi, and see what could not be mapped. Free.

Export, diff and the command line

Export to SVG, PNG and PDF, or copy the picture to the clipboard. Compare two revisions of a diagram as two diagrams. penstock runs the same checks from a terminal or a pipeline, and serves them to an AI agent over MCP.

Engines

A project targets one of five engines. The choice decides which modeler is built, which groups the properties panel shows, and which namespace is written into the file. Give each folder its own penstock.yaml and a repository can hold both a Camunda 7 and a Camunda 8 project side by side.

Camunda 7 The Camunda Platform modeler, the camunda namespace, script tasks that open as IDE tabs, and /engine-rest for deployment and Monitor.
Camunda 8 The Camunda Cloud modeler, the zeebe namespace, connector element templates, and the Zeebe REST gateway for deployment and Monitor.
Operaton The Camunda 7 modeler with the operaton namespace, which reads a camunda: diagram as it is and offers to convert the namespace. Deploys and Monitors on /engine-rest like Camunda 7.
CIB seven The Camunda 7 modeler and the camunda namespace, with generated tests in its own Java packages. Deploys and Monitors on /engine-rest.
Classic BPMN 2.0 Plain bpmn-js, no engine namespace at all, and Inputs and Outputs written the way BPMN defines them. For a diagram meant for no engine in particular.

Getting started

  1. Open a .bpmn file

    It opens in the diagram editor. The editor tabs at the bottom switch to the raw XML and back, so nothing is hidden from you.

  2. Or create an example

    With no diagrams in the project, the tool window offers to write a small order process that runs against a local Camunda 7 or Camunda 8 engine, with workers, test cases and the commands to run it.

  3. The engine is found for you

    It comes from penstock.yaml, or from the diagram itself. Only an empty new diagram asks, in one line above the canvas, and the answer goes into penstock.yaml.

  4. Add connector templates, if you are on Camunda 8

    Keep them in .camunda/element-templates, next to the diagram or in any folder above it, list other folders under elementTemplates in penstock.yaml, or install them from the connector browser.

Validation with bpmnlint

bpmnlint needs no setup. The editor marks problems on the elements as you draw and lists them in the Problems tab, and penstock check runs the same rules in a terminal. Without a configuration the rules are bpmnlint:recommended; a .bpmnlintrc in the project root replaces them: 

{
  "extends": ["bpmnlint:recommended"],
  "rules": {
    "label-required": "error",
    "no-implicit-split": "warn"
  }
}

Custom rules come from a bpmnlint-plugin-{name} package in the project’s node_modules. The command line reads it from there; the editor needs those rules compiled into a bundle, named by lint.clientBundlePath in penstock.yaml. See Validation.
