BPMN diagrams, in the IDE you already use.

Penstock opens .bpmn and .bpmn20.xml files in a visual modeler inside JetBrains IDEs, right next to the raw XML. Process models stay in the project and in version control, so they are reviewed the same way as code.

Install from JetBrains Marketplace Any JetBrains IDE from 2025.2 · Free, with 30 days of Pro

What it does

Three modeling profiles

Classic BPMN 2.0, Camunda 7 and Camunda 8, chosen per project. The palette and the properties panel follow the profile.

Properties panel

Edit element properties, including the Camunda extension attributes, without leaving the diagram.

Inline scripts as real files

Groovy and JavaScript inside a script task open as an IDE tab with syntax highlighting and completion, and are written back into the diagram as you type. Camunda 7.

Element templates

Load Camunda 8 connector templates from the project - a .camunda/element-templates folder is found without setup - or pick them from the built-in template browser.

Deployment

Deploy the open diagram to Camunda 7 REST or Camunda 8 in one click, to the profile penstock.yaml puts in force, with basic auth or OAuth 2.0. Credentials go to the IDE password safe, never to a project file.

Validation

bpmnlint runs without any setup, with its recommended rules or the project’s own .bpmnlintrc, and marks errors and warnings on the diagram itself.

Auto layout

Reformats a diagram you already have — separates overlapping elements, aligns sequence flows and routes connections orthogonally — in one click, with Undo in the message that follows. Pro.

Token simulation

Step a token through the process to check that the flow behaves the way the model says it does.

Export and navigation

Export… in the More menu saves the diagram as a picture. The Penstock tool window lists every BPMN, DMN and form file in the project.

Getting started

  1. Open a .bpmn file

    It opens in the diagram editor. The editor tabs at the bottom switch to the raw XML and back, so nothing is hidden from you.

  2. The engine is found for you

    It comes from penstock.yaml, or from the diagram itself. Only an empty new diagram asks, in one line above the canvas, and the answer goes into penstock.yaml.

  3. Add connector templates, if you are on Camunda 8

    Keep them in .camunda/element-templates, next to the diagram or in any folder above it, list other folders under elementTemplates in penstock.yaml, or install them from the built-in browser.

Validation with bpmnlint

bpmnlint needs no setup. The editor marks problems on the elements as you draw and lists them under Rules in the diagram check, and penstock check runs the same rules in a terminal. Without a configuration the rules are bpmnlint:recommended; a .bpmnlintrc in the project root replaces them: 

{
  "extends": ["bpmnlint:recommended"],
  "rules": {
    "label-required": "error",
    "no-implicit-split": "warn"
  }
}

Custom rules come from a bpmnlint-plugin-{name} package in the project’s node_modules. The command line reads it from there; the editor needs those rules compiled into a bundle, named by lint.clientBundlePath in penstock.yaml. See Validation.
