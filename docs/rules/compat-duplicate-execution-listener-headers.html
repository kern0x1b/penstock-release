Two headers of a listener with the same key

compat/duplicate-execution-listener-headers · Engine compatibility · Error: the diagram or the process is wrong

Why it matters

A listener that reads a header by its key gets one of the two values, and which one is not defined.

How to fix it

Give each header of the listener its own key.

In penstock check and in the editor the rule is called compat/duplicate-execution-listener-headers. In .bpmnlintrc it is turned off as camunda-compat/duplicate-execution-listener-headers or as compat/duplicate-execution-listener-headers.
