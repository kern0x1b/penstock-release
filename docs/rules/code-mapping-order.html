Guide / Every rule

A mapping line reads a value an earlier line was meant to set

The check code/mapping-order, in the group Diagrams and code.

AdvicePro

Why it matters

The engine evaluates the source of every mapping line before it writes any target, so a later line that reads what an earlier one sets gets null - camunda#11789.

How to fix it

Move the value into the earlier line, or compute both from the same source.

Where you see it

The Problems tab lists it under Code. In a terminal, penstock code reports it with the file and line. This check is part of Penstock Pro, and Team in a pipeline.

Rule details

Idcode/mapping-order
GroupDiagrams and code
LevelAdvice: it works, and reads or runs better without it
