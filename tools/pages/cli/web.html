Start it

penstock web ./processes
penstock web
penstock web ./processes --port 9000 --no-open
  1. Run penstock web [folder]. With a folder it opens that project. Without one it starts on a welcome page where you choose the project in the browser, and the recent ones are one click away.
  2. The command prints what it serves, the link, and how to stop it: 
    Serving /home/me/processes
  http://127.0.0.1:8765/?token=...
Press Ctrl+C to stop.
    With no folder the first line is No project is open yet. Choose one in the browser.
  3. A browser opens on the link by itself. With --no-open you open the link yourself.
  4. Work in the page. See Penstock Web for the window.
  5. Press Ctrl+C in the terminal to stop the server. It says Stopping. and exits with 0. A second press leaves at once.

The server starts on port 8765. When that port is busy it tries the next one, up to 99 higher, and says Port 8765 is in use, so Penstock uses 8766. If none of them is free it stops with No port from 8765 to 8864 is free.

Options

OptionWhat it does
--port <port>The port to listen on, 8765 by default. The next free one is used when it is busy. 0 takes any free port. The value should be a number from 0 to 65535.
--host <address>The address to listen on, 127.0.0.1 by default. Any other makes the folder reachable from the network, and the command prints a warning. See Who can reach it.
--no-openPrint the link and do not open a browser.
--profile <name>Use this profile, as PENSTOCK_PROFILE would.

The folder you give should exist and be a folder. The command refuses a filesystem root or a home folder that holds no penstock.yaml and no .git. It says This folder is too large to be a project; give the folder of the diagrams. See Every command for the exit codes.

Who can reach it

The server is made for one person on one machine, and nothing is sent anywhere.

  • Only this machine. It listens on 127.0.0.1. With --host set to an address that is not the machine's own loopback, anyone who can reach the machine and holds the link can read and change the diagrams of the open project, and see folder names on the machine. The command prints that warning.
  • A key on every request. Every request needs the key of this run. The link carries it once. The page that answers the link keeps it in a cookie the page's own scripts cannot read, then reloads without it. When the browser is opened by the command, the link holds a code that works once and expires after a minute, so the key is not in the process list. The key is never logged.
  • Only its own page. A request whose Host is not the server's own, or that comes from another web page, is refused before anything else.
  • Only the project folder. Paths are resolved inside the folder, and anything that leaves it, contains .. or points into .git is refused. The server writes only diagrams, decisions, forms, test cases, element templates and penstock.yaml.
  • Bounded. A request has two minutes, bodies are limited to 1 MB (24 MB for a file), and a file over 64 MB is not read.
  • Hooks need trust. The deployment hooks of penstock.yaml run only in a project that penstock trust knows. Passwords are kept in memory for the run.

A link never picks a folder. A project is opened by the folder argument or by the folder browser, which lists folder names only, never a file's contents. Opening, closing or switching a project moves everything with it: a request made for the previous project is answered with an error instead of being served from the wrong folder, and a switch is refused while a deploy runs.

What it remembers

Your choices live in ~/.penstock/preferences.json, the file the other tools use, or under PENSTOCK_HOME when that is set. It is readable by its owner only.

recentProjectsThe projects on the welcome page and in the project switcher.
webSessionsWhat was open, one entry for each project folder: the tabs, the groups and how they are split, and the tree.
projectTreeWidth, projectTreeHiddenThe width of the sidebar, between 240 and 400 pixels, and whether it is shown.
webAutosaveSecondsThe seconds without an edit after which a file is written. Absent means no autosave.
themeFollow the system, light, dark or Dracula.
suggestNextBlock, suggestionsWhether the editor suggests the next element and names, sources and expressions. Both are on unless set to false.
showCodeBadgesWhether the small marks that say whether the code behind a task was found are drawn.
aiChatoff, bottom or sidebar: where the AI chat is.
languageServersYour own language servers. See below.

Code in the page

A class or a bean that a diagram names opens in a read-only code tab. Code tabs and the XML text of a file are highlighted for Java, Kotlin, Scala, C#, Python, Go, Groovy, JavaScript, TypeScript, JSON, YAML, XML, SQL, Markdown and properties files, in the colours of the editor's theme.

For completion, hover, diagnostics and go to definition, the page talks to a language server that is installed on the machine that runs penstock web. Penstock looks for these on the PATH:

Without a server the tab still highlights, and says Highlighting only. Install the server to get completion, hover and go to definition here. with the name of the server. To use another server, or another command line, add it under languageServers in ~/.penstock/preferences.json. An entry of yours with the same id as a preset replaces the preset.

{
  "languageServers": [
    {
      "id": "my-java",
      "languages": ["java"],
      "command": "/opt/jdtls/bin/jdtls",
      "args": ["-data", "/tmp/jdtls-workspace"],
      "env": { "JAVA_HOME": "/opt/jdk" }
    }
  ]
}

A line of code that a diagram element names, such as a job type, a topic, a class, a bean or a message, gets a marker beside its line number and a hover that names the diagram and the element. A click opens the diagram on that element. In the XML text of a file, completion offers the job types, topics, classes, beans and message names that the project shares with its code. Links between diagrams and code are part of Pro, as in every tool.

Common problems

"This page has lost its link to Penstock."
The key belongs to one run. After penstock web was restarted, use the link it printed in the terminal. Unsaved changes stay in the browser and come back when you open the project again.
"The port should be a number from 0 to 65535".
Give --port a whole number, or leave it out.
"The address should be an IP address or a host name".
Check --host. Leave it out to listen on this machine only.
"The editor page is not part of this build, so only the API answers."
The installation lacks the editor page. Install the command line again with npm install -g @kern0x1b/penstock-cli. Setting PENSTOCK_WEB_ROOT to a built page serves that page instead.
"Penstock is unable to open a browser."
Open the link above the message yourself.
"The server is serving another project now."
The project was changed in another tab. Reload the page to follow it.
"Running tests from code needs an IDE."
The page does not run the tests of a worker. Run penstock scenarios run in a terminal. See scenarios run.
