The Run tests panel and the test cases themselves are described once in Run tests, and code tests and coverage in Code tests and coverage. This page is about how they use the IDE.

Run test-case files in the test runner

  1. Open a test case file, for example orders.json.
  2. Click the green triangle in the gutter next to a test case. Or right-click the file or a folder and run it.
  3. The IDE's Run window shows a test tree, pass or fail, and the log. Double-click a test to open it in the file.

The run uses the profile in force, or the one the run configuration names. The trace of each run is kept under .penstock/runs/, and its path is in the log. The same safety rules apply as everywhere: the engine must be marked for tests, or you confirm a local one once.

The run configuration

Running a test-case file creates a run configuration called Penstock test cases. It takes a file or a folder of test cases and a profile. You can run it again from the run widget at the top right of the IDE, like any other run configuration.

Run and debug code tests from the diagram

  • Right-click an element on the canvas, or the empty canvas, and choose Run code tests or Debug code tests. It runs the test methods that name the element or its process, with the project's own test runner. When you debug, the diagram shows where the process stops.
  • In the Penstock tool window, each process lists its tests with how much of it they cover. The Code tests node lists every code test by class. Run or debug any of them, a class, or all. Run All Code Tests is on the tool window's toolbar.
  • Code Vision above a test says how much of each process it covers.

Coverage

After the code tests have run with Camunda Process Test, or on Camunda 7 with the process test coverage extension, Coverage appears on the editor's toolbar. It reads the reports under target or build and follows them as the tests run again.

What you see

  • A test tree with pass or fail, and the log, in the Run window.
  • A green triangle in the gutter of each test case.

Common problems

The Run window says the engine is not marked for tests.
Set deployment.forTests: true on the profile, or confirm a local engine when asked.
There is no Coverage button.
No test report was found yet. Run the code tests first.
There is no green triangle in the gutter.
The file is not a Camunda Process Test JSON test-case file, or Pro is not active.
