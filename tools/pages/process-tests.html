Three tools, one idea

A process with two gateways has several ways through it. Each way is a scenario. Penstock finds them all, and then:

  • Paths lists the scenarios, as a test plan you can read.
  • Tests writes a JUnit test for each scenario.
  • Coverage shows which elements your tests reached.

List the ways through

$ penstock paths .
src/main/resources/order-process.bpmn  2 scenario(s)
   1. Order received → Approve order → Charge card → Decide shipping method → Shipment confirmed → Send receipt → Order completed
   2. Order received → Approve order → Charge card → Card declined → Payment declined
        Card declined fires on Charge card

Each scenario shows the decision taken at each gateway and its condition. Use --format md for a checklist to paste into a test plan, or --format json for a tool. In the IDE, run Run Penstock | Paths from the tool window. The MCP tool is list_scenarios.

$ penstock paths . --format md
### 1. Order received → Order completed

- [ ] runs Approve order → Charge card → Decide shipping method → Shipment confirmed → Send receipt

Write the tests

  1. Run penstock tests .. In the IDE: Run Penstock | Tests.
  2. Penstock writes one JUnit class per process, with a test for every way through it.
  3. The command names the test dependencies your build is missing. Add them.
  4. Run the tests with your normal test runner.
$ penstock tests .
wrote src/test/java/io/penstock/example/process/OrderProcessTest.java  2 scenario(s)

The tests need these test dependencies in pom.xml:
  io.camunda:camunda-process-test-java:8.9.21

2 test(s) in 1 class(es), one per way through each process.

Each test starts the process with variables chosen to take that way: a value just past each condition, and at a default flow a value no other condition accepts. It completes the jobs, user tasks and external tasks, correlates messages, moves time past timers, throws errors from jobs where an error boundary is taken, and checks the elements the run passed.

Run and debug tests from the diagram

Pro

  • Right-click an element on the canvas, or the empty canvas, and choose Run Tests or Debug Tests. It runs the test methods that name the element or its process, with your project's own test runner.
  • In the Penstock tool window, each process lists its tests with how much of it they cover. A Tests node lists every process test by class. Run or debug any of them, a class, or all. Run All Process Tests is on the toolbar.
  • When you debug, the diagram shows where the process stops.

Coverage

Pro

  1. Run your process tests. Use Camunda Process Test, or on Camunda 7 the process test coverage extension.
  2. A button Coverage appears on the toolbar. Press it.
  3. The diagram colours what the tests reached and dims what they did not.
  4. The panel lists the tests with how much of the diagram each covers. Pick one to see the way it takes. It also lists the elements no test reaches.
  5. Run the tests again. Coverage follows.

Penstock reads the reports under target or build. Code Vision above a test says how much of each process it covers.

Common problems

There is no Coverage button.
No test report was found yet. Run the process tests first. Reports must be under target or build.
The generated test does not compile.
Add the test dependencies the command printed to your build file.
The tests went to the wrong place.
Set tests.out and tests.package in penstock.yaml.
"To fill in".
A way that the data cannot choose is marked for you to finish. Fill in the variables that take it.
I want to run scenarios against a live engine without JUnit.
Use Runs and test cases. They need no build setup.
