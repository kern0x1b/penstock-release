What it is

The sidebar is one surface in all three editors, and it is where most of what Penstock adds to a diagram is read. It sits to the right of the canvas and carries a row of tabs along its top. Each editor registers its own tabs, in a fixed order, so the tabs you know from a diagram are in the same place in a decision or a form.

With the sidebar open and an element selected, you can go from what the diagram says to the engine, to the files and back without leaving the editor. Editing a diagram covers the canvas beside it.

The tabs

EditorTabs, in order
A diagramProperties, Scenarios, Problems, Monitor, Code
A decisionProperties, Problems
A formProperties, Preview, Problems

The row shows the tabs as icons when the sidebar is narrow, with a tooltip that names each one, and a count badge on Problems. A tab with nothing to show says what it is for and what to do next, rather than staying blank.

Open and close it

The sidebar toggle is the last thing on the toolbar, at the right edge, and it stays pressed while the sidebar is open. It is the Sidebar action, so it is also in the More menu and the command palette.

{{host:sidebar-toggle|Open the sidebar}}

How wide, and what it remembers

The sidebar takes about a third of the width of the editor, between 320 and 480 pixels, and the dividing line can be dragged from 280 pixels to half the editor. Below about 840 pixels wide it becomes a drawer over the canvas rather than a column beside it, so nothing on the page is pushed sideways on a phone.

The width, and the tab you left selected, are kept in ~/.penstock/preferences.json, so they are the same in every tool on the machine. Problems, Monitor and Code each keep their own state while you look at another tab, so Monitor holds the instances it fetched and Code holds what you had open. The tabs choose what you look at; going deeper inside one is a separate step, and a small ‹ in the tab's own header takes you back.

What each tab is for

PropertiesThe settings of the selected element, in the groups the engine defines. The properties panel.
ScenariosThe ways through this process, generated from the diagram or written by hand, and run against an engine. Scenarios.
ProblemsEverything the check found, in groups. Diagram check.
MonitorWhat the engine is doing with this diagram now: incidents, and the instances waiting at each step. Monitor.
CodeThe workers, classes, beans, tests and usages behind the selected step. Code links.
PreviewA form as a user sees it, beside the JSON it is given. The form editor.

Only the tabs of the editor you have open are there. A diagram has no Preview tab, because a form is the only thing that previews.

What you see

  • A column beside the canvas with a row of tabs along its top.
  • A count badge on Problems while the check has findings.
  • Icons instead of names when the sidebar is narrow.

Common problems

The sidebar is gone.
Press the sidebar toggle at the right of the toolbar, or the Sidebar action in the More menu.
Monitor says there is no engine.
It asks for the address of the profile in force. Monitor has what to set.
Scenarios says it needs Pro.
Scenarios is Pro on your machine and Team in a pipeline. Plans and licence.
A tab is missing.
Each editor has its own tabs: Scenarios, Monitor and Code are for diagrams, Preview for forms. The table above says which.
