What is a worker

A service task does not do the work itself. A worker, a program of yours, does. On Camunda 8 the task names a job type. On Camunda 7 it names a topic. If no worker is running for that name, the task waits forever. Check Workers finds that out.

Steps

  1. Open the Penstock tool window and find Workers.
  2. Right-click Workers, or select it and use its action: Check Workers on <engine>. If your project uses several engines it says Check Workers on the Engines.
  3. Penstock asks each diagram's engine, using the profile in force for that diagram's folder. A project with a Camunda 7 folder and a Camunda 8 folder asks both.
  4. Each worker in the tree now says what the engine said. The Workers node shows checked at 14:02.

When the engine is asked

Only when you run it, with the profile's credentials. See Security and privacy.

Free and paid parts

Check Workers is part of Pro's code links. The code check, which compares diagrams with your code and does not ask an engine, is described on its own page.

Common problems

"The engine does not report job statistics, which it does from Camunda 8.9".
Your Camunda 8 is older than 8.9. Use the code check instead. It compares diagrams with your code.
"The engine refused the question (403)".
The profile's user may not read jobs. Use a user that may.
There is no Check Workers action.
The project has no worker tasks yet, or Pro is not active. Without Pro the tool window shows a Code line that offers to buy or sign in.
It says "no jobs" for a worker that runs.
Only the last 24 hours count on Camunda 8, and only open tasks on Camunda 7. A quiet worker looks quiet.
