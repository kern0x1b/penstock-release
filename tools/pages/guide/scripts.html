Why

The small editor in the properties panel is fine for one line. For a longer script you want the full IDE. Penstock hands the script to the IDE as a file and writes every keystroke back into the diagram.

Steps

  1. Select a script task, or any element that holds a script: a condition, an input or output mapping, an execution listener or a task listener.
  2. In the properties panel, find the script field. Under it is a button Edit in new tab. Press it.
  3. The IDE opens a new editor tab. The file has the extension .groovy for Groovy or .js for JavaScript, so the IDE's own colours, completion and inspections apply.
  4. Type. Your changes go back into the diagram about 100 milliseconds after each keystroke, and reach the diagram model 400 milliseconds after you stop.
  5. Close the tab when you are done.

What you see

  • While the tab is open, the field in the properties panel is read-only. There is exactly one place to type.
  • The tab is a temporary file kept in memory. Nothing is written to your disk.
  • When you close the tab, the field in the panel becomes editable again.
  • If you press the button again while the tab is open, the IDE brings that tab to the front. It does not open a second one.

The default language

Set scriptType in penstock.yaml to groovy, javascript or none. It is used for a script that has no format yet, and for a condition expression that has no language yet. It applies to Camunda 7, Operaton and CIB seven only. See penstock.yaml.

Common problems

There is no Edit in new tab button.
The button exists for Camunda 7, Operaton and CIB seven. In Camunda 8 a script is a FEEL expression and is edited in the panel.
The IDE colours the script as the wrong language.
The script format is JavaScript or Groovy as set on the element. Change the script format in the panel and open the tab again.
I closed the tab and lost text.
You did not lose it. Everything you typed was already written back into the diagram. Undo in the diagram if you need an older version.
