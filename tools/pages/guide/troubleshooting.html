First, run the doctor

In a terminal run penstock doctor. In the IDE, right-click in the Penstock tool window and choose Run Penstock | Doctor. It prints the settings files that apply, the engine, the profiles, and whether the engine answers. Most problems show up right there.

The editor area is blank

  1. Check that your IDE is version 2025.2 or newer.
  2. The diagram editor is a browser view (JCEF) inside the IDE. An IDE that cannot supply JCEF cannot show a diagram. JetBrains' own downloads run on the JetBrains Runtime, which has it. If you pointed the IDE at another Java runtime, point it back.
  3. Right-click inside the blank area. If there is an Open DevTools entry, use it to see the error.
  4. Use the Text tab. The XML is never locked away.

The editor needs no licence. A paid feature explains itself when you reach for it. The rest keeps working.

A file does not open in its editor

  • The BPMN file type covers bpmn, bpmn.xml and bpmn20.xml. The DMN type covers dmn. If such a file opens as plain XML, the pattern may have been given to another file type in Settings | Editor | File Types. Move it back.
  • A .form file opens in the form editor only if it is a Camunda Form: a JSON object with components. Other .form files stay with the IntelliJ GUI Designer.
  • The tool window lists only files inside a project content root. A diagram kept outside is not listed.

Check and lint findings do not appear

No markers on the canvasThe linting button on the canvas turns them off and on. It is hidden while token simulation runs. The findings are also under Rules in the check card.
"The bpmnlint rules could not run"Your .bpmnlintrc uses a bpmnlint plugin. The editor loads plugin rules only from a bundle named by lint.clientBundlePath. See Validation.
My own rules are ignoredlint.configPath is relative to the project root. penstock doctor prints the path and says if it is missing.
"Running Penstock requires trusting this project first"The command-line actions start an external process, which the IDE allows only in a trusted project. Trust the project and run it again.
"Penstock could not start"The actions run penstockw, or npx when there is none. node and npx must be on the PATH the IDE inherited. Start the IDE from a terminal to test.

Deployment fails

When the engine answers with anything outside 2xx, the message repeats the status and the engine's own answer. Read that first. It is the engine talking. A request that never arrived says Could not reach the engine at <url>.

No engine addressNeither deployment.url nor the Connection dialog gives one for the profile in force. Use Connection… in the menu next to Deploy.
404 on Camunda 8Use the address of the REST API. Penstock adds /v2/deployments. An address that ends in /v2 works too.
401 or 403The user or the client may not deploy. Check the sign-in type, user, and secret in Connection….
OAuthA failed token request is reported apart: the endpoint could not be reached, answered with an error, or sent no access_token.
"The preDeploy hook failed, nothing was sent"Read the hook's output that follows. In an untrusted project a configured preDeploy is not run, and the deployment stops.
Certificate errorsPenstock has no option to skip certificate checks. Trust the certificate in the Java runtime of the IDE.
Timeouts10 seconds to connect, 30 seconds for the request, 15 for the token.
Wrong password savedOpen Connection…, type the right one, Save and Deploy. Set Sign in to Not needed and save to forget it.

See Deployment.

Element templates do not appear

Templates come from .camunda/element-templates folders next to the diagram or above it, and from elementTemplates in penstock.yaml. The Classic editor ignores them, so check the engine first. A listed path that does not exist adds nothing and says nothing in the editor. penstock doctor reports it as missing. A file over 10 MB is skipped, and a file that is not valid JSON is skipped with a line in the IDE log. See Element templates.

The connector browser is empty or cannot download

  • Press Retry, or Check for updates.
  • It needs to reach api.github.com and codeload.github.com, through the IDE's proxy settings. See Security and privacy.
  • If it worked before, Penstock uses what it downloaded and says Could not check for a newer release.
  • From a terminal: penstock connectors --refresh.

The diagram was changed on disk

A dialog File Changed on Disk asks Reload or Keep Editing. See The BPMN editor.

A paid feature asks me to buy Pro

Your trial may have ended. Run penstock license to see what this machine has. See Buying and signing in.

Test cases will not run

  • is not marked deployment.forTests: mark the profile, or confirm once in a terminal or the editor.
  • A step waits and fails: no worker took it in time. Start the worker or mock the step.

See Runs and test cases.

Where else to look

  • The IDE log: Help | Show Log in Finder (or Explorer). Penstock logs under jetbrains.bpmn.editor. Swallowed failures, such as a template that would not parse, are there with a stack trace.
  • DevTools in the editor: right-click the diagram and choose Open DevTools to see a frontend error.
  • The list of files Penstock reads and writes.
  • The questions and answers.

Still stuck

Open an issue on the support tracker. Add the IDE version, the plugin version, the engine, the output of penstock doctor, and a .bpmn file that shows the problem. Security problems go to SECURITY.md, not to a public issue.
