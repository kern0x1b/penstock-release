What it is

The example is an order process. A user approves the order. A worker charges the card. A decision picks the shipping method. The process waits for a message that the parcel has shipped. Then a receipt is sent. If the card is declined, the order ends early.

There are two versions. Pick the engine you use.

Camunda 8Camunda 7
Card is charged byA Spring Boot job worker for the job type charge-cardAn external task worker for the topic charge-card, a plain Java client in worker/
Receipt is sent byA Node job worker for the job type send-receiptA Java delegate, SendReceiptDelegate
EngineYou run one, for example Camunda 8 RunPart of the example: a Spring Boot app with the engine, the REST API and the web apps on an in-memory database
Deployment addresshttp://localhost:8080/v2http://localhost:8080/engine-rest

Write it into a folder

From the command line

  1. Make an empty folder and go into it.
  2. Run penstock init --example camunda-8. For Camunda 7, run penstock init --example camunda-7.
  3. Read the list of files it wrote. Penstock also writes the penstockw wrapper scripts, and adds penstock.local.yaml to .gitignore. See Command line.

The folder must be empty. If it is not, Penstock stops and writes nothing. It never overwrites your files. A .git folder does not count as content.

From the IDE

  1. Open an empty project.
  2. Open the Penstock tool window. It offers Camunda 8 order process and Camunda 7 order process when the project has no diagrams yet.
  3. Press one and confirm with Create.
  4. A notification says where the example is and that its README says how to run it.

Run it

The README written into the folder has the exact commands and versions. In short:

  1. Start the engine. On Camunda 8, start Camunda 8 Run. On Camunda 7, run mvn spring-boot:run. The web apps open at http://localhost:8080. The login is demo and demo.
  2. Look at the diagrams in the editor, or check them: penstock check .
  3. Deploy the process, the decision and the form: penstock deploy . On Camunda 7 they are also deployed when the app starts.
  4. Start the workers, each in its own terminal.
  5. Start an order. A home order under 1000 is paid and ships standard. Use "amount": 5000 to see the card declined.
  6. Approve it in Tasklist, then send the message shipment-confirmed to tell the process the parcel has shipped.

Run the test cases

Run penstock test-cases .. It deploys a test build, mocks the workers and runs the three cases against your local engine. The first run on a local engine asks once whether it may. See Runs and test cases.

The three cases are:

  • A home order is approved, paid, shipped standard and completed.
  • An order from abroad ships internationally.
  • A declined card ends the order without a shipment.

What you see

This is what the check prints in the Camunda 8 example:

$ penstock check .
ok    src/main/resources/approve-order.form
ok    src/main/resources/order-process.bpmn
ok    src/main/resources/shipping-method.dmn

And this is what penstock paths . prints. It lists the two ways through the process:

src/main/resources/order-process.bpmn  2 scenario(s)
   1. Order received → Approve order → Charge card → Decide shipping method → Shipment confirmed → Send receipt → Order completed
   2. Order received → Approve order → Charge card → Card declined → Payment declined
        Card declined fires on Charge card
  • The check finds nothing wrong. Every task has a worker, the decision and the form exist, and the drawing is clean.
  • In the Penstock tool window the process shows its workers, its message, its decision, its form and its error code.
  • The test cases run in the terminal, or in the IDE from the gutter next to each case.

Common problems

"is not empty. An example is written into an empty folder"
Run the command in a new, empty folder. Penstock refuses to write into a folder that has files, so nothing of yours is overwritten.
"Unknown example"
The only names are camunda-8 and camunda-7.
Deploy says the engine is not reachable.
Start the engine first, and check deployment.url in penstock.yaml. See Deployment.
The test cases ask a question the first time.
Test cases deploy a test build. On a local engine Penstock asks once before it does. See Runs and test cases.
